# 助言AI(phase-advisor)

発話ごとに、ユーザが求めている工程の候補と、引き上げ方向の注意を文脈へ差し込む `UserPromptSubmit` フックです。**既定は無効**です。

- 本体: [`.claude/hooks/phase-advisor.mjs`](../../.claude/hooks/phase-advisor.mjs)(Node 22、依存パッケージなし)
- 設定: `process.config.json` の `phaseAdvisor`(強制層。変更は人が行う)
- 判断記録: process-compass ADR-0054

この標準で「判定」は、人が行うゲート判定を指します。この部品は判定をしないため、**助言AI**と呼びます。

## 何をして、何をしないか

| する | しない |
| --- | --- |
| 工程の候補と対応スキルを示す(確信度0.8未満は出さない)。release では、人が判定することを示す | ゲートの合否判定・承認 |
| 注意を示す: 取り消せない操作 → `needs-owner`、統制の弱化 → `needs-platform`、技術判断 → `needs-tech`、禁止事項1〜5。エージェントには、該当するかを自分で確かめてから経路に従うよう求める | 完了方向のラベル遷移(`dev-done` / `ready-to-merge` ほか)の根拠になること |
| 実装の依頼に F-NNN があれば照合する: `docs/gates/g4-F-NNN-*.md` の有無と、最新の記録の結果欄が「通過」か。コードで判定し、`/implement` の呼び出しでも外部送信なしで行う | 遮断(`decision: "block"` を返さない) |
| 版・確率・遅延を `.claude/phase-advisor.log` に残す(発話の本文は残さない) | 「該当しない」と書くこと。**注意が出ないことは、問題が無いことを意味しない** |

判定の根拠にしない理由は、標準の第5章 5.5 / 5.7.4 / 5.8.3 です。確率で判定する分類器の出力は、人に注意を向けさせる材料に限ります。

### 送らない場合

次のどれかに当たると、外部へは送りません。

- 無効のとき
- 3つの記録(外部送信の決裁と決裁した送信先・ツールの採用・モデルの採用)のどれかが空、または `TODO` のような仮の値のとき
- 決裁した送信先と `endpoint` が一致しないとき
- `endpoint` がフックの許可リストに無いとき
  - 許可されるのは `https://api.typesafe.ai` と、ローカルで動かす互換実装(`http://127.0.0.1` / `localhost`)だけ
  - 許可リストの変更は、フック本体(強制層)の変更として扱う
- 環境変数 `TYPESAFE_API_KEY` が無いとき
- 秘匿情報らしき文字列を含むとき。例: `AKIA…`、`ghp_…`、`sk-…`、秘密鍵、`PASSWORD=…`
- 作業スキル7種の呼び出し(`/spec-write`、`/implement` ほか)
- 6文字未満の発話

### 失敗したとき

- API の失敗・2.5秒の時間切れ・応答の版の不一致では、助言を出しません。リダイレクトも追いません
- 次の原因では助言が止まり続けるため、`systemMessage` で**人へ知らせます**
  - 設定の不備
  - 版の不一致
  - HTTP 401 / 403 / 404 / 410
  - 秘匿情報の検出
- 一時的な失敗(時間切れ、429、5xx)は記録するだけです

## 有効化の手順

決める人がそれぞれ違います。**ひとりが兼ねる場合も、記録は分けて残します**。

1. **採否**: 技術判断者(G-3、`state:needs-tech`)が、案件で採るかを判断記録に残します。
2. **外部送信**: オーナー(`state:needs-owner`)が決裁します。決裁記録の場所を `approval.dataTransfer.record` に、決裁した送信先を `approval.dataTransfer.endpoint` に書きます。材料は次のとおりです。
   - **送るもの**: 発話の全体(4,000字まで)。貼り付けた文章も含みます
     - Claude Code がタグ付きで渡した貼り付けだけは、`quoted_material`(1,500字まで)として分けて送ります
     - 対話 CLI の既定ではタグが付かないため、分けずに送ります
   - **送信先**: TypeSafe。米国でホストされます
   - **保持**: 期間の定めはありません。ZDR は enterprise 契約だけです
   - **学習**: 同意なしに学習へは使われません
3. **ツールの採用**: AI維持管理者(`state:needs-platform`)が承認し、その記録を `approval.toolAdoption` に書きます。
4. **API キー**: 組織のシークレット管理から、環境変数 `TYPESAFE_API_KEY` で渡します。リポジトリには置きません。
5. **モデルの採用**: AI運用担当者が、評価用の基準集合で回帰評価(適合性評価)を行い、結果を見て記名で承認します(標準 3.12.3)。その記録を `approval.modelAdoption` に書きます。
6. `phaseAdvisor.enabled` を `true` にします。

`/process-init` で構成を作り直しても、`phaseAdvisor` の値(有効化・閾値・決裁記録)は引き継がれます。

## 評価結果

合成した日本語の発話240件で評価しました。正解ラベルは Claude が付けたもので、人は確認していません。

閾値を決めるのに使っていない発話での値は次のとおりです。

- 工程の正解率: 約85%。確信度0.8以上に絞ると、対象は約75%、正解率は約96%
- 注意の再現率: 約91%
- 注意の要らない発話で注意が出た割合: 約7%

方法と詳細は、process-compass の ADR-0054 と評価メモ(research/20260923-jev-phase-advisor-evaluation.md)にあります。

## 限界

- **評価の妥当性**: 正解ラベルは Claude が付けたため、Claude と同じ読み方をするほど点が高く出ます。人による抜き取り確認は済んでいません。発話は合成したもので、実際の案件の発話ではありません。
- **日本語**: 提供元は、英語以外の精度は劣ると明記しています。自組織の発話で測り直してください。
- **過信**: 第三者の測定では、未知の規則や答えの無い問いに対して、確信度1.00のまま誤ることがあります。
- **敵対的な入力**: 指示を含む文章を貼り付けると、答えが動く可能性があります。タグの無い貼り付けは分けて送れません。評価にタグ付きの例は含まれていません。
- **秘匿情報の検出**: 既知の形に限ります。検出を逃れた秘密は送られます。
- **提供元**: 2026-09-15 公開の early access で、SLA がありません。レート制限は予告なく変わります。価格の持続性も示されていません。
- **閾値**: 上の値は jev-1.13.0 と、この評価で決めたものです。版を切り替えたら基準集合で測り直し、閾値を変えるかは人が判断します。自動では更新しません。

## 版を切り替えるとき・送信先を変えるとき

- **版を変えるとき**: 事前に基準集合で現行と比べ、差分を記録します。そのうえで AI運用担当者が承認し直します(`approval.modelAdoption`)。
- **送信先を変えるとき**: 送信先ごとに所在国・保持・学習の扱いが違います。そのため**オーナーの決裁をやり直します**(`approval.dataTransfer`)。あわせて、フックの許可リストの変更を AI維持管理者が承認します。
- **ローカル実行の互換実装**: 存在はしますが、このテンプレートでは検証していません。
