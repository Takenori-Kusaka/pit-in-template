## 欄の書き方

| 欄 | 書くこと |
| --- | --- |
| ID | `D-` + 連番。再利用しない |
| 区分 | **負債** / **例外** / **未解決** / **類似検知** のいずれか。下表による |
| 対象 | 区分「例外」の行では必須。例外を適用する変更または成果物。変更は、PR の番号(`PR #12`)またはコミットの識別子(先頭7桁以上)で書く。`Issue #12` のように前に PR 以外の語がある番号は、PR を指すものとして読まれない。ゲートの判定基準を満たさないまま、その**ゲートの判定**を進める例外(変更でなく判定が対象)は、ゲートと判定記録の対象で `G-2 F-001`(案件の段階のゲートは `G-1 P-001`)と書く。この形の行は、変更の例外承認として対応づけない。区分「類似検知」の行では、検知した変更(PR の番号、またはコミットの識別子)を書く。この記入は、新しい行を書くときだけの義務。「負債」「未解決」の行は「—」でよい。ただし、安全関連部の検証の記録で故障挿入の試験項目を省く根拠に使う行は、行を書いた時期によらず、対象に「基準7」か「安全関連部の検証の記録」の語を書く(機械は語の有無と、G-7 以外のゲート名が「基準7」の直前に付いていないかだけを見る。`G-5 基準7` のような書き方は数えない。対象の文が当該の試験項目を正しく指すかは人が確かめる) |
| 内容 | 何を妥協したか。「リファクタが必要」ではなく、具体的に |
| 受容した理由 | なぜそのとき受け入れたか |
| 顕在化の兆候 | **観測できる事象で書く**。「そのうち問題になる」は兆候ではない |
| 返却の目安 | 時期またはステージ。事業ステージによって扱いが変わる。区分「類似検知」の行は**日付**(YYYY-MM-DD)で書く(出荷判定者が突合の日と比べるため。集約による比較は降りていない)。期限のない記録を認めない。区分「未解決」の行は、対処の担当者の記名も書く(区分「例外」の回収責任者と同じく、この欄に書く) |
| 状態 | 未返却 / 返却済み(日付) / 不要になった(理由)。区分「例外」の行は、未返却 / 返却済み(日付) / 取り下げ / 失効 のいずれか。**未返却が有効を指す** |
| 記録者 | 台帳へ書き込んだ者 |
| 承認した者 | 区分「例外」の行では必須。例外承認の権限を持つ者(D-0 表1「例外承認」の決定者)の記名。記録者とは別の欄に書く。作成を指示した者と AI の名義は書けない。「負債」「未解決」「類似検知」の行は「—」でよい |

## 区分

**どの経路で台帳へ入ったかを区別します**。混ぜると、ゲートを止めるべきものと止めないものが見分けられなくなります。

| 区分 | 由来 | ゲートへの影響 |
| --- | --- | --- |
| **負債** | 意図して受け入れた妥協(行わないと決めた品質の活動を含む。例: 設計の細部の文書化、細かいレビューの見送り) | 通過を妨げない |
| **例外** | 標準 7.3 の例外承認。**判定基準を満たさないまま進めた** | 回収まで継続的な報告の対象 |
| **未解決** | 標準 7.3.2。**判定基準には含まれないが放置できない事項** | 通過を妨げない。期限までに解消しない場合、例外か前提の受容へ送る。ゲートでない決定の未達の行は、見直しの期日に再び宣言し直す |
| **類似検知** | 標準 第4章「類似が検知された場合の措置」。**当該の変更単位で処理を完了できなかった検知** | 返却目安の期限を過ぎた未返却の行が残る出荷を、出荷判定者が止める(G-7 基準8) |

**未解決の行には、判定の外にある理由を「受容した理由」の欄へ書きます**。「G-2 の判定基準に含まれない」のように、どのゲートの何に含まれないかを書きます。

**この区分が無いと、判定基準に含まれない事項が判定へ持ち込まれます**。

**未解決の行には、対処の担当者を「返却の目安」へ書きます**(標準 7.3.2)。「記録者」は台帳へ書き込んだ者であり、担当者ではありません。

**コア機能の理解の保持者が1名以下の是正**(標準 第3章 3.4.3 要求事項6): 新しい区分や欄を足さず、区分「負債」の行として書きます。対象を `コア理解: <コア機能の名前>`(運用引き継ぎ文書の節2 の名前と同じ文字列)とし、返却の目安に是正の期限と責任者を書きます。対象の先頭にこの語が無い行は、是正の行として見分けられません。台帳へ登録しても列挙に無い離脱は解けず、保持者を2名以上にするまで続きます。期限つきの受容は D-0 節15 で行います。

**ゲートでない決定の未達**(適用: 市場・顧客仮説の検証を担う者がいない場合。標準 第8章): 新しい区分や欄を足さず、区分「未解決」の行として書きます。内容に未達の理由(顧客接点の不在、予算の不在のいずれか、または両方)と調達先、受容した理由に代償措置、返却の目安に見直しの期日と担当者を書きます。調達先が決まっていなければ、空欄にせず「未記入」と書きます。この未達の行は、見直しの期日に再び宣言し直します。**代償措置は、未検証であることの記録と見直しの期日の設定に限り、未達の解消に数えません**。ゲートの未達の宣言は、構成の `unmet[]` で行います(`.claude/skills/gate/gates/G-1.md`)。

**類似の検知の実施記録**(適用: 出荷判定 G-7 の基準8。標準 第4章「類似の検知の実施記録」)

類似の検知を実施した出荷では、次の4つの事項を記録します。道具の種類と水準は定めません。置き場は、出荷判定の判定記録の備考、または `docs/` の下の記録のどちらかとし、所在を判定記録に書きます。

| 事項 | 書くこと |
| --- | --- |
| 用いた手段 | 道具の名前と版、または人による照合の旨 |
| 対象の範囲 | 検知の対象にしたコード・成果物の範囲 |
| 実施日 | YYYY-MM-DD |
| 結果 | 一致の件数と、それぞれの処置(書き直す / 許諾の条件を満たす / 取り除く / 台帳へ記録して先へ進める) |

- 当該の変更単位で処理を完了できなかった検知だけを、区分「類似検知」の行として本台帳に置く。処理を完了した検知は、行を足さず、実施記録の結果に書く
- 類似の検知を実施しなかった出荷は、基準8 を満たさない。先へ進めるには、標準 第7章 7.3 の例外承認による(区分「例外」の行)
- 集約が見るのは、依存関係のライセンス検査の記録の有無までである。上の4事項の有無と、手段が実際に走ったかは、出荷判定者が読んで判定する。類似の検知の結果の良否は判定しない

## 例外承認の記録(区分「例外」の行)

区分「例外」の行は、標準 第7章 7.3 の例外承認の記録です。記録は5つの事項を、次の欄に持ちます。

| 7.3 の事項 | 台帳の欄 |
| --- | --- |
| 対象 | 対象 |
| 状態 | 状態(未返却が有効) |
| 承認した者 | 承認した者 |
| 理由 | 内容(満たさない基準の項目番号)、受容した理由(満たさない理由) |
| 期限 | 返却の目安(回収の期限と回収責任者) |

出荷判定の証跡の集約(`aggregate-evidence`)は、次をすべて満たす行だけを、変更の例外承認として対応づけます。対応づかない行は、理由を品質レポートに出します。

- 「対象」の欄が、当該の変更(PR の番号、またはコミットの識別子)を明示している。**内容や他の欄に番号が現れるだけの行は対応づけない**
- 状態が「未返却」(有効を示す値)と完全に一致する。返却済み・取り下げ・失効の行と、「未返却(…)」のように書き足した行は対応づけない。回収済みの行を、別の変更の例外承認として使い回さない
- 承認した者・理由(内容と受容した理由)・期限(返却の目安)が記入されている。期限は日付(YYYY-MM-DD)を含む。「未定」「—」、様式の文言(<…>)は記入として扱わない
- 承認した者が人の名簿の人へ対応づき、その人が当該の変更の作成を指示した者でない。AI の名義でない。氏名の空白・括弧書き・敬称、アカウントの @ の有無は正規化して照合する。名簿の人へ対応づかない記名は対応づけない

「対象」がゲートの判定(`G-2 F-001` の形)の行は、変更の例外承認とは別に照合します。状態が有効を示す値の行について、承認した者・理由・期限が記入され、承認した者が名簿の人で AI の名義でないことを確かめ、成立しない行を欠落として出します。その判定がどの基準を欠いたか、承認した者が成果物の作成者と別の人かは、機械では確かめません(G-7 で出荷判定者が判定記録と突合します)。

**状態「失効」と期限超過**(標準 第7章 7.3): 回収の期限(返却の目安の日付)を過ぎた例外承認は、期限の翌日から効力を失います。状態が「未返却」のまま期限を過ぎた行と、状態「失効」の行は、変更の例外承認として対応づけず、記録の欠落として扱います(対象が出荷の範囲の外の行、ゲートの判定を対象とする行も数えます)。回収したら状態を「返却済み(日付)」にします。期限を延ばす場合は、行を書き換えず、新しい行で承認し直し、元の行にその行の識別(D-NNN)を書きます。承認し直された元の行は、欠落に数えません。区分「類似検知」の行の返却目安も書き換えません。その延長は、区分「例外」の新しい行で承認し、新しい行の「対象」に元の行の ID(D-NNN)を書きます。

承認した者が例外承認の権限を持つかは、機械では確かめません(内部監査で確かめます)。「対象」と「承認した者」の欄を持たない旧い様式の台帳は、例外承認を対応づけられません。欄を足してください。

**ファストトラックの例外承認**(適用: 標準 第7章 7.4。区分「例外」の行)

ゲートの短縮を期日を理由に承認する行は、次を書きます。

- **短縮できる対象**は標準 7.4 の限定列挙(`.claude/skills/gate/reference/exception-paths.md`)に限る
- **受容した理由**に、期日の種類と外部の根拠を書く。適用できる期日は、遅延したときに組織の外部で不可逆な損失が生じるもの(顧客との納品契約、公開日、規制の法定期限、サービス終了に伴う移行期限)に限る。社内の目標日・見込み・上位者の期待・意欲的な目標は適用できない。外部の不可逆性の判定は人が行う
- **内容**に、短縮するゲートと、検証されないまま残る範囲(ファイル・機能・受入基準の単位)、未解決欠陥の一覧と重大度(欠陥の台帳の所在でよい)、影響を受ける利用者の範囲を書く
- **内容の先頭**に、印 `ファストトラック(短縮: <ゲート>)` を書く(例: `ファストトラック(短縮: G-6)`。括弧の中には短縮するゲートだけを書く)。G-5 は、印の括弧の中が G-4・G-5・認証・認可・データ保全を名指す行と、未回収の印の行が同じ台帳に残る間の新しい印の行を、例外承認として対応づけない。印の無い行は、機械がファストトラックの行として見分けられない(印の付け忘れは機械で捕まえない。確かめる者: G-7 の出荷判定者と内部監査)。期限内の事後レビューと、未実施のときの権限の停止は機械で閉じない(確かめる者: 出荷判定者と内部監査)
- **返却の目安**に、回収の期限と回収責任者に加えて、回収に要する見積工数を書く
- 申請書の草案は、AI が起こしてよい。承認した者の記名は人が書く

## 出荷判定との関係

G-7 は「受容した負債が台帳に記録されているか」を確認します。**記録漏れが0件であること**が判定基準です。負債の量そのものは判定しません。

記録されていない妥協は、出荷判定で見つかりません。見つかるのは、後で壊れたときです。
