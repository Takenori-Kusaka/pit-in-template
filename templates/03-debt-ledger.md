## 欄の書き方

| 欄 | 書くこと |
| --- | --- |
| ID | `D-` + 連番。再利用しない |
| 区分 | **負債** / **例外** / **未解決** のいずれか。下表による |
| 対象 | 区分「例外」の行では必須。例外を適用する変更または成果物。変更は、PR の番号(`PR #12`)またはコミットの識別子(先頭7桁以上)で書く。`Issue #12` のように前に PR 以外の語がある番号は、PR を指すものとして読まれない。「負債」「未解決」の行は「—」でよい |
| 内容 | 何を妥協したか。「リファクタが必要」ではなく、具体的に |
| 受容した理由 | なぜそのとき受け入れたか |
| 顕在化の兆候 | **観測できる事象で書く**。「そのうち問題になる」は兆候ではない |
| 返却の目安 | 時期またはステージ。事業ステージによって扱いが変わる |
| 状態 | 未返却 / 返却済み(日付) / 不要になった(理由)。区分「例外」の行は、未返却 / 返却済み(日付) / 取り下げ / 失効 のいずれか。**未返却が有効を指す** |
| 記録者 | 台帳へ書き込んだ者 |
| 承認した者 | 区分「例外」の行では必須。例外承認の権限を持つ者(D-0 表1「例外承認」の決定者)の記名。記録者とは別の欄に書く。作成を指示した者と AI の名義は書けない。「負債」「未解決」の行は「—」でよい |

## 区分

**どの経路で台帳へ入ったかを区別します**。混ぜると、ゲートを止めるべきものと止めないものが見分けられなくなります。

| 区分 | 由来 | ゲートへの影響 |
| --- | --- | --- |
| **負債** | 意図して受け入れた妥協 | 通過を妨げない |
| **例外** | 標準 7.3 の例外承認。**判定基準を満たさないまま進めた** | 回収まで継続的な報告の対象 |
| **未解決** | 標準 7.3.2。**判定基準には含まれないが放置できない事項** | 通過を妨げない。期限までに解消しない場合、例外か前提の受容へ送る |

**未解決の行には、判定の外にある理由を「受容した理由」の欄へ書きます**。「G-2 の判定基準に含まれない」のように、どのゲートの何に含まれないかを書きます。

**この区分が無いと、判定基準に含まれない事項が判定へ持ち込まれます**。

## 例外承認の記録(区分「例外」の行)

区分「例外」の行は、標準 第7章 7.3 の例外承認の記録です。記録は5つの事項を、次の欄に持ちます。

| 7.3 の事項 | 台帳の欄 |
| --- | --- |
| 対象 | 対象 |
| 状態 | 状態(未返却が有効) |
| 承認した者 | 承認した者 |
| 理由 | 内容(満たさない基準の項目番号)、受容した理由(満たさない理由) |
| 期限 | 返却の目安(回収の期限と回収責任者) |

出荷判定の証跡の集約(`aggregate-evidence`)は、次をすべて満たす行だけを、変更の例外承認として対応づけます。対応づかない行は、理由を品質レポートに出します。

- 「対象」の欄が、当該の変更(PR の番号、またはコミットの識別子)を明示している。**内容や他の欄に番号が現れるだけの行は対応づけない**
- 状態が「未返却」(有効を示す値)と完全に一致する。返却済み・取り下げ・失効の行と、「未返却(…)」のように書き足した行は対応づけない。回収済みの行を、別の変更の例外承認として使い回さない
- 承認した者・理由(内容と受容した理由)・期限(返却の目安)が記入されている。期限は日付(YYYY-MM-DD)を含む。「未定」「—」、様式の文言(<…>)は記入として扱わない
- 承認した者が人の名簿の人へ対応づき、その人が当該の変更の作成を指示した者でない。AI の名義でない。氏名の空白・括弧書き・敬称、アカウントの @ の有無は正規化して照合する。名簿の人へ対応づかない記名は対応づけない

承認した者が例外承認の権限を持つかは、機械では確かめません(内部監査で確かめます)。「対象」と「承認した者」の欄を持たない旧い様式の台帳は、例外承認を対応づけられません。欄を足してください。

## 事業ステージによる扱い

| ステージ | 扱い |
| --- | --- |
| S0 探索(PoC) | 記録のみ。返却しない |
| S1 価値確立(MVP) | 記録 + 返却目安 |
| S2 スケール(グロース) | 計画返却を開始 |
| S2 安定運用 | 定常の返却サイクル |

## 出荷判定との関係

G-7 は「受容した負債が台帳に記録されているか」を確認します。**記録漏れが0件であること**が判定基準です。負債の量そのものは判定しません。

記録されていない妥協は、出荷判定で見つかりません。見つかるのは、後で壊れたときです。
