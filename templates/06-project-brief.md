# 企画書(事業意図)

`docs/project-brief.md` として置きます。企画承認(G-1)の判定対象です。

**前提条件**: D-0(体制図)が承認済みであること。未承認では審議を開始できません。

## 1. 観点1 戦略整合
案件を始める理由を書かないまま、費用と効果の数字だけで判定する経路を作らないための項目です。

| 項目 | 内容 |
| --- | --- |
| 対応する戦略目標 | 自社や組織のどの戦略目標(OKRs等)に紐づくか |
| 開始する本質的な理由 | なぜいま、この案件に取り組む必要があるのか |
| **対応が成立しなくなる条件** | 外部環境の変化など、前提が崩れて取り組む意味が失われる条件 |

## 4. コア機能の候補・スコープ・マイルストーン

### コア機能の候補
プロダクトの価値を決定づける中核機能です。**「全部コア」または「全部非コア」は不可**です。

- **コア機能の候補**: (例: LLMを活用した独自の高精度検索抽出)
- **非コア機能の候補**: (例: パスワードリセット、標準的なPDFエクスポートなど、差別化にならない機能)

### スコープ外(やらないこと)
やらないことを明確に定義することで、スコープクリープを防ぎます。

- **スコープ外**: (例: 本システム以外での直接のマスターデータ編集、リアルタイムの同期連携)
