# 企画書(事業意図)

`docs/project-brief.md` として置きます。企画承認(G-1)の判定対象です。

**前提条件**: D-0(体制図)が承認済みであること。未承認では審議を開始できません。

企画は6つの観点で評価します。**下の並びは書く順序です**。財務を最初に置きません。

## 戦略整合(観点1)

| 項目 | 記載 |
| --- | --- |
| 対応する戦略目標 | 「成長」等の一般語は不可。組織が定めた目標を識別できる形で書く |
| 対応が成立しなくなる条件 | どの前提が変われば、この案件が戦略目標へ寄与しなくなるか |

## 自社が勝てる理由(観点2)

自社の何の資産・能力が、他社にはなく、この案件の成否を左右するか。**「知見がある」「実績がある」は不可**。何の知見・何の実績かを書きます。

| 項目 | 内容 |
| --- | --- |
| 現在の代替手段 | **「ない」と書かない**。手作業でも代替手段である |
| その代替手段が使われ続ける条件 | 移行の費用・ライセンス・調達要件など、乗り換えが起きない側の事情 |

## 投資対効果(観点4 / G-1 基準1)

| 項目 | 概算 |
| --- | --- |
| 初期開発費 | |
| コンテキスト基盤の初期整備費 | 用語集・設計標準・既存資産の取り込みの工数。**ゼロは不可** |
| 運用費(年) | |
| 期待効果(短期) | 観測できる時期と、その時点で確かめられる変化 |
| 期待効果(長期) | **幅で記載する。単一の年額を書かない** |
| 算定根拠 | |
| 参照した過去案件 | 自組織の実績を1件以上。無い場合は「参照できる過去案件なし」と記載 |
| **効果が出ない条件** | ここを空欄にしない |

単一の年額を求めない理由は、**要求すると書き手がその数字を作る**ためです。市場規模・投資回収期間・損益分岐点の欄も置きません。

### 稟議へ数値を出すとき

決裁制度が単一の金額を要求する場合は、**期待効果の幅の下限値**を用います。**上限値を提示してはなりません**。数値には算定根拠と効果が出ない条件を併記します。

**この欄を稟議のために書き換えないでください**。作法は[附属書G](https://takenori-kusaka.github.io/process-compass/phase4-process-design/executive-projection/)によります。
