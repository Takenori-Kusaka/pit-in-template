# AI エージェント安全リスクアセスメント表

`docs/safety-risk-assessment.md` として置きます。**適用条件に該当する場合のみ**必要です。承認済みの本表が企画承認(G-1)の前提条件になります。

手順と記号の定義は[標準 第6章](https://takenori-kusaka.github.io/process-compass/phase4-process-design/deliverable-templates/)によります。

## 適用条件

次のいずれかに該当する場合に必須です。該当しなければ作成しません。

- [ ] 開発対象が物理的な危険源をもつ機器・設備を制御する
- [ ] エージェントの適用範囲にリスク区分 R1 の変更種別が含まれる
- [ ] エージェントが本番環境の資源へ到達できる
- [ ] エージェントの AI 自律レベルが L2 以上である

**人員や期日の制約でこの表を省略できません**。危害の深刻度は体制の都合で下がりません。

更新は**実行環境の設定を変更したとき**に行います。定期更新は求めません。

## 記号

本表の記号は、**案件の安全重要度(CL)やリスク区分(R)とは別の軸**です。同じ数字でも意味が異なります。

| 記号 | 意味 | 値 |
| --- | --- | --- |
| Hz-nnn | 危険源の識別子 | 案件内の連番 |
| Hs1 / Hs2 / Hs3 | 危害のひどさ | 3が最も重い |
| Ex1 / Ex2 / Ex3 | 危険源への暴露(頻度と時間) | 3が最も多い |
| Oc1 / Oc2 / Oc3 | 危険事象の発生確率 | 3が最も高い |
| Av1 / Av2 / Av3 | 危害の回避または制限の可能性 | 3が最も回避しにくい |
| SR1 / SR2 / SR3 / SR4 | 安全リスク区分(見積りの結果) | 4が最も高い |
| RRS1 / RRS2 / RRS3 | リスク低減ステップ | 段階を表す固定値 |

**危害のひどさを CL で書かないでください**。CL は案件ごとの安全重要度であり、危険源1件の低減で動く値ではありません。

接続は2つです。

- **AI 自律レベル(L)と実行形態(E)は Ex を決める入力です**。引き上げる場合は本表を再評価します
- **SR2 以上の残留リスクの受容は、R1 の決定として扱います**

## 判定の規則

- **SR4 が1件でも残る間は、当該のエージェント運用を開始してはなりません**
- 計算式は定めません。SR の判定根拠を文章で書きます
- 低減策の適用後に生じた新たな危険源を点検し、危険源の同定へ戻ります

## 危険源の同定

洗い出しには次の分類を用います。参照 ID は OWASP Top 10 for Agentic Applications の分類を指します。

| 危険源カテゴリ | 内容 | 参照ID |
| --- | --- | --- |
| 目的の乗っ取り | 外部データを介して目的・判断経路が操作される | ASI01 |
| ツールの誤用 | 曖昧な指示や過剰な権限により、正当なツールが危険な形で使われる | ASI02 |
| 権限の濫用 | 権限が個別に統制されず、権限昇格やなりすましが起きる | ASI03 |
| 供給網の汚染 | 実行時に読み込む第三者のツール・データに汚染が混入する | ASI04 |
| 未検証コードの実行 | 生成したコードをレビューを経ずに実行する | ASI05 |
| 記憶とコンテキストの汚染 | 記憶や参照データの汚染により、以後の判断が恒久的に歪む | ASI06 |
| エージェント間通信の露出 | エージェント間の指示が傍受・偽装・再送される | ASI07 |
| 連鎖的な障害 | 1体の異常がネットワーク全体へ伝播する | ASI08 |
| 人間の信頼の悪用 | 権威づけや擬人化により、人間に有害な判断をさせる | ASI09 |
| 目的からの逸脱 | 誤った指標を最適化し、意図した機能から外れて振る舞う | ASI10 |

**「人間の信頼の悪用」を省いてはなりません**。承認ゲートを設けても、承認者が内容を読まずに通すのであれば保護方策は機能しません。

## リスク低減の3ステップ

| 段階 | 内容 | エージェントにおける実装 |
| --- | --- | --- |
| RRS1 | 本質的安全設計方策 | 危険な行為を実行できない環境にする、または帰結を回復可能にする |
| RRS2 | 安全防護・付加保護方策 | 危険を検知し、停止または承認を求める |
| RRS3 | 使用上の情報 | 残留リスクを関係者へ周知する |

RRS1 は**設定ファイルとして実装します**。実行環境の隔離、外部通信の既定拒否、書込み範囲の限定、ツール許可リスト、認証情報の分離、破壊的操作の代替設計、帰結の可逆化が該当します。実装場所を低減策の欄へ書きます。

**RRS3 でリスクを下げてはなりません**。「手順書に記載したため対策済み」とする扱いは、段階の順序に対する違反です。

## 完全版で追加する項目

物理的な危険源を持つ案件では、軽量版に次を加えます。

| 項目 | 内容 |
| --- | --- |
| 制御構造図 | エージェント・人間・CI・対象システムの制御関係を図示する |
| 不適切な制御動作の一覧 | 「与えない」「与える」「早すぎる/遅すぎる」「長すぎる/短すぎる」の観点で危害に至る条件を列挙する |
| システム状態別の評価 | 通常運転・起動・停止・異常・保守の各状態で評価する |
| 反復の記録 | 低減策の適用後に生じた新たな危険源と、再評価の結果 |
| 設定ファイルへの参照 | RRS1 の各項目が、どの設定のどの項目として実装されているか |

```markdown
## 6. 不適切な制御動作(完全版)
| ID | 制御動作 | 観点 | 危害に至る条件 | 対応する Hz |
| --- | --- | --- | --- | --- |
| UCA-01 | | 与えない / 与える / 時期 / 継続時間 | | |

## 7. 反復の記録(完全版)
| 回 | 追加した低減策 | 新たに生じた危険源 | 再評価の結果 |
| --- | --- | --- | --- |
```

## 記入時の注意

- Ex は「そのツールが呼ばれる頻度」と「自律実行が継続する時間」の積で見積もる
- Av は**承認ゲートの存在ではなく実効性**で評価する。承認が形式化している工程では、回避しにくい側へ見積もる
- 低減策には実装場所を書く。文章だけの記載は RRS3 とみなし、RRS1 および RRS2 として数えない
