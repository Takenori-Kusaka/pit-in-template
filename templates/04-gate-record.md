# ゲート判定記録

`docs/gates/<ゲート>-<対象>-<日付>.md` として置きます。例: `docs/gates/g4-F-012-2026-08-08.md`

**この記録の作成をもって、ゲートの判定が成立します**。判定基準がすべて充足していても、記録が無ければ未判定です。Issue のクローズ・PR のマージ・`state:*` ラベルの遷移は、判定の成立要件ではなく事務です。

| 項目 | 値 |
| --- | --- |
| ゲート | G-4 機能仕様承認 |
| 対象 | F-012 |
| 判定者 | <氏名>。**1人**。合議体にしない |
| 判定日時 | YYYY-MM-DD HH:MM |
| 結果 | 通過 / 差し戻し |
| 確定の形態 | 人確定 / 協働 / 委任 |
| 参照した D-0 の版 | <`docs/D-0-governance.md` の `version`> |
| 変更のリスク区分 | R1 / R2 / R3(変更を対象とする判定のみ) |
| リスク区分を確定した者 | <氏名。機械の規則による分類は、規則の所在。起案者の自己記載のままなら「自己記載」> |
| 期限内か | はい / いいえ(超過した場合は日数も) |

**対象**には、判定の対象を1つ書きます。変更を対象とする判定(G-6、PR を経ていないコミットの区分の確定など)は、PR の番号(`PR #12`)またはコミットの識別子(先頭7桁以上)で書きます。委任の期間ごとの保証の開示への G-8 は、期間の起点と終点を書きます(例: `委任の期間 2026-09-01〜2026-09-30`)。出荷判定の証跡の集約は、この欄で記録と変更を対応づけます。

結果は**この2値だけ**です。欄には「通過」か「差し戻し」の語だけを書き、転記の注記などは本文へ書きます(`next.mjs` は語の完全一致で読み、注記を足した値を通過に数えません)。「中止」「保留」は投資の継続可否であり、ステージ移行ゲートが判断します。**「条件付き通過」を書いてはなりません**。条件を付して先へ進める場合は、この記録に加えて例外承認の手続を踏み、回収の期限と回収責任者を技術負債台帳へ登録します。

**確定の形態**は、1つだけ残します。どの形態でも、判定者は席の責任者(人)です。**AI の確認を判定として記録しません**。

| 確定の形態 | 意味 |
| --- | --- |
| 人確定 | 人が判断し、理由を自分で書いた。**R1 の決定と例外承認は人確定に限る**。G-8 とステージ移行の判断も委任しない |
| 協働 | AI が起案した判断の案と根拠を、人が変更ごとに確認して確定した。挙動要約と判定の記名は人が行う |
| 委任 | 登録した範囲で先へ進めた変更を、独立レビュアの席の責任者が事後の抜き取りで確かめた。**事後確認の記録**であり、事前の承認の記録ではない。作成を指示した者と別の人を置けず、責任者本人が抜き取った場合は、その旨を書く |

G-6 の判定を事後の抜き取りへ移した変更(独立レビュアの席の委任に当たり、R3 と記録された変更)は、事前の承認の記録を持ちません。これを「人の事前確認を経ていない変更」と呼びます。開発者の席だけの委任の変更は、独立レビュアの事前の承認の記録を持ちます。人の事前確認を経ていない変更ではありません。抜き取られていない委任の変更を、人の判定と同じ語(承認、通過、独立レビュー済み)で記録してはなりません。変更単位の識別は、コミットのトレーラ `Delegated: <規則ID>` に残します。

確定の形態が「委任」の G-6 の記録は、事後の抜き取りの記録です。出荷判定の証跡の集約は、これを独立した人の確認(事前の承認)に数えません。抜き取った変更の一覧として出します。

**リスク区分を確定した者**には、区分を確定した人を記名します(標準 第3章 3.8.1)。AI は草案を書けますが、確定は人が行います。区分が起案者の自己記載のままである場合は「自己記載」と書きます。出荷判定の証跡の集約(`aggregate-evidence`)は、確定した者の記名が無い場合、保証の開示の項目3 へ「自己記載だけに依る」と表示します。

**参照した D-0 の版**には、判定の時点で有効な体制図の版を書きます。体制の変化点の後は、改訂後の版を参照して判定します。構成が追随する版と一致しない判定記録は、出荷判定の証跡の集約(`aggregate-evidence`)が欠落として扱います。成立済みの判定記録の版は、変化点の後も書き換えません。

## 判定に持ち込まないもの

当該ゲートの判定基準に無いものです。**空欄で提出できません**。

| 対象外 | 扱う場所 |
| --- | --- |
|  |  |

**「扱う場所」を必ず書きます**。行き先を書かない除外は、判定者から「では、これはどこで見るのか」と問われ、答えが無ければその場で扱われます。**通過済みの他ゲートと、未達（`unmet`）として宣言済みの項目は、ここへ書きます**。

## 差し戻しの理由

差し戻した場合のみ記入します。**チェックリストの項目番号で示します**。

> 項目2を満たしていません。受入基準3に対応するテストが見つかりません。

「もう少し検討してください」は理由になりません。基準のないゲートは、判定者の属人判断になり、滞留と素通しの両方を招きます。

## 再判定の場合のみ

| 欄 | 記載 |
| --- | --- |
| 前回の判定記録 | <リンク。**上書きしません**> |
| 再判定の理由 | <どの前提が、何によって崩れたか。実測を示す> |
| 今回の判定の対象 | <前回から変わった部分だけか、全体か> |

**再判定のために新しいゲートを設けません。会議体も設けません**。同じゲートを、同じ判定者が、同じ基準で判定し直します。

**前回の判定記録を上書きしません**。当時なぜ通したかを失わないためです。

**判定に持ち込まないものへ、通過済みの他ゲートを必ず書きます**。再判定の場は、他ゲートの蒸し返しの場になりやすいためです。

## 挙動要約(G-6 のみ)

独立レビューでは、レビュアが**自分の言葉で**1〜2文を書きます。

> 招待の一覧に失効の表示を足す変更。取り消し API は失効時に 409 を返すようになった。

**AI に生成させてはなりません**。要約は理解の証拠であり、生成物は証拠になりません。この欄は文書の体裁を整えるためのものではなく、承認者が対象を理解したことの記録です。

## 監査対応書式(適用: 構成 `review.recordFormat` が `audit` の体制、または `independentSafetyAssessment` が真の体制。G-6)

規制業(第8章 軸C)と安全重要度 CL2 以上(軸E)の構成で、G-6 の判定記録に足す表です。構成が要しない体制では書きません。出荷判定の証跡の集約は、構成が要する体制で、**変更ごとに G-6 の判定記録があり、この表が埋まっていること**を確かめます。PR の承認だけでは記録になりません。

| 欄 | 記載 |
| --- | --- |
| 2人目の判定者 | <氏名。G-6 を2名で行う体制(構成 `review.reviewerCount` が 2)で、1人目と別の名簿の人。合議ではなく、各自が独立に判定する。2人目本人が自分で記名する。1名の体制は「該当なし(承認者 1 名の体制)」> |
| 2人目の挙動要約 | <2人目が**自分の言葉で**1〜2文。1人目の要約を写さない。空欄の記名は、独立した人の確認に数えない> |
| 安全性の評価者 | <実装の責任者(開発者の席の責任者)・作成を指示した者・当該の判定者から**組織的に独立**した評価者の氏名(附属書F)。安全関連でない変更は「該当なし(理由)」。構成 `independentSafetyAssessment` が真の体制で要する> |
| 安全性の評価の記録の所在 | <評価の記録(危険源との対応、合否)の所在。評価者を記名した場合に要する> |

- 2人目の判定者は、PR の2件目の承認(各自の挙動要約つき)または2人目自身の判定記録でも代えられます。この表に書く場合は、2人目本人が記名と挙動要約を書きます。**1人目が2人目の欄を埋めてはなりません**
- 承認者の数が構成の要求に満たない変更は、出荷判定の証跡の集約が「G-6 の承認者 N 名 / 要求 M 名」として、独立した人の確認を経ていない変更に数えます
- 独立した安全性の評価は、独立レビューへ吸収しません(第4章 G-6)。機械が確かめるのは記名の有無と独立(名簿の人で、実装の責任者・指示した者・判定者と別人)までで、評価の実施と内容は確かめません

## 決断の記録(適用: G-8・ステージ移行ゲート・例外承認)

この3つの場面でのみ記入します。それ以外のゲートでは、提示された内容を読んで判定すれば足ります。

| 欄 | 記載 |
| --- | --- |
| 確認した事項 | 判断の根拠として実際に確認したもの |
| **確認していない事項** | 確認しなかった範囲。**空欄および「なし」は記録として無効** |
| 判断が変わる条件 | どの事実が異なれば別の判断になるか |
| 受容したリスク | 受容した内容と、顕在化した場合の対処。G-8 では、保証の開示に載った未達・未測定の受容と、異議の扱いを含める |
| 出荷判定者の異議(リリース決裁 G-8 の記録に限る) | 異議の有無。異議がある場合は、開示されたどの事実への異議か。無い場合も「異議なし」と書く。**第4章 G-8 の4事項に当たる場合は、理由を書く**(品質レポートの「出荷判定者の異議で検討する事項」に出る)。「異議なし」とする場合も同じ。**空欄と、事項に当たるのに理由が無い記載は、記載の欠落** |
| 照らした層1 の版(G-8 に限る) | <受容を照らした品質保証の方針と受容の基準(`docs/quality-assurance-policy.md`)の版。層1 が無い組織は「層1 なし」。**空欄は記載の欠落**> |
| 上申(G-8 に限る。段階を超える受容・異議を退けた受容) | <届けた先(層1 の項目5)と日付(YYYY-MM-DD)。該当しない場合は「該当なし」。**空欄と、異議を退けて受容したのに届けた日付が無い記載は、記載の欠落**> |
| 品質保証の対象外として出荷することの受容(G-8 に限る) | <層1 の項目4 の権限者の記名。保証の主張の成立判定に、成立しない変更が無い場合は「該当なし」。**成立しない変更があるのに記名が無い記載は、記載の欠落**> |

G-8 の3行(照らした層1 の版・上申・対象外の受容)は、事業決裁者が受容を層1 の受容の基準と権限の段階に照らして行ったことの記録です(第4章 G-8「受容の基準との照合と上申」)。

- 事業決裁者の段階を超える残存リスクは、単独で受容しない。層1 の項目5 の上申先へ届け、上位の権限者が受容または拒否を記名する
- 出荷判定者の異議を退けて受容した場合は、受容は成立したまま、退けた事実と理由を層1 の項目5 の上申先へ必ず届ける
- 層1 の「受容しない条件」に当たる残存リスクと、外枠(法令・契約・整合規格)の不充足は、受容の対象にしない
- 機械が確かめるのは、3行の記載の有無、異議を「異議あり」と書いて通過にした記録に上申の日付があること、対象外の受容の記名が自然人で層1 の権限者の席の責任者と一致することだけ。段階を超えたかどうかは判定しない(出荷判定者・内部監査が確かめる)
- **社内の受容は、外部への責任を限定しない**

委任で先へ進めた変更の、期間ごとの保証の開示(`aggregate-evidence --period-from --period-to`)への受容と異議も、この欄に書きます。「対象」へ期間の起点と終点を書きます。期間の開示のための様式を、別に設けません。

「確認していない事項」がこの様式の要です。**全部を確認したという記録は、確認の範囲を書いていないだけです**。

## 停止の申し立ての解除(適用: 第7章 7.11 の解除の記録)

停止の申し立て(PR へ受信箱のラベル `state:stop-requested` を付ける)で保留した PR を、保留から解く記録です。この節は解除の記録でだけ書きます。冒頭の表は、ゲート欄を「停止の申し立ての解除」、対象を `PR #<番号>`、判定者を解除する人、判定日時を解除の日時、結果を「通過」(解除する)として書きます。

| 欄 | 記載 |
| --- | --- |
| 申し立てた者 | <記名> |
| 申し立ての内容 | <品質・安全・法令上の異常として、何を認めたか> |
| 解除の理由 | <解除する人が自分で書く。空欄の解除は受け付けない> |
| 申し立てた者の見解を退けたか | 退けた / 退けていない(申し立てた者が取り下げた、または異常を解消した) |
| 上申先と日付(退けた場合) | <層1 の項目5「停止の申し立てを退けた解除の届け先」と日付(YYYY-MM-DD)。退けていない場合は「該当なし」> |

- **解除の記録は、基底ブランチ(既定ブランチ)へ先に入れます**。G-5(`pr-rules`)は基底ブランチの記録だけを読みます。保留した PR の中で足した記録は数えません
- 解除する人は、層1(テンプレ11)の項目4「停止の申し立ての解除」の受容者の席の責任者です。層1 が無い、または行が空欄の組織では、事業決裁者の席の責任者を権限者として照合します(出力にその旨が出る)
- **AI の名義の解除を受け付けません**。ラベルを外しただけでは解除になりません(ラベルを付けた履歴を読める場合、解除の記録が無ければ失敗のまま)
- 申し立ては拒否権ではありません。解除の権限を申し立てた者へ移しません。申し立てた者と解除する者が同一人物の体制(1名体制など)では、その旨が出ます
- 申し立ての件数を、申し立てた者・受けた者・チームの評価の減点に用いてはなりません(層1 の項目1)

標準 第7章 7.7.8 の評価を、判定の記録の中に残す欄です。**評価のための様式を別に設けません**。ステージ移行ゲート(SG)と第三者による棚卸し(第7章 7.7.6)の判定記録でだけ書きます。判定者は B-2 の決定者です。

| 欄 | 記載 |
| --- | --- |
| 評価の単位 | <案件、または開発ライン> |
| 下流の指標と比較の基準値 | <企画書の「AI の利用で期待する成果」の指標ごとに、今回の値・基準値・基準値の出所。「基準値なし」の場合はその旨> |
| 総費用の内訳 | <企画書の総費用の内訳(5区分 × 実績 / 見積り)を、評価の時点の実績で更新して転記する。見積りの区分は「見積り」と書く> |
| 評価に用いなかった入力 | <自己申告の速度、AI の利用量を入力にしていないこと。入力にした場合、評価は無効> |
| 判定 | <標準 第3章 3.7.3 の4値(継続 / 中止 / 保留 / 差し戻し)と、縮小の場合はその手段(自律レベル・運用形態の引き下げ、範囲の縮小、停止)> |
| 縮小・停止の基準に当たる状態での継続 | <該当する場合は、第7章 7.7.5 の要求事項の充足。該当しない場合は「該当なし」と書く> |

- **節の欠落と、空欄の欄は記載の欠落**です。ゲート欄に「ステージ移行」または「棚卸し」を含む判定記録で、出荷判定の証跡の集約が検査する
- 総費用の内訳は企画書(テンプレ6)から転記する。AI の実行費用だけを費用と見ない

## 比較した選択肢(適用: リスク区分 R1 の決定・例外承認)

**R1 の決定と例外承認でのみ記入します**。例外承認の記録そのもの(対象・状態・承認した者・理由・期限)は、技術負債台帳(テンプレ3)の区分「例外」の行に置きます。出荷判定の証跡の集約が変更に対応づけるのは、台帳の行だけです。リスク区分は**変更ごとに判定します**。案件の安全重要度から、この欄の適用外を導いてはなりません。

| 案 | 到達点 | 残るリスク | 採否 |
| --- | --- | --- | --- |
| | | | |

案とリスクの見積は AI が提示してかまいません。**どの案を選ぶかの理由は人が記入します**。

## 未消化のテスト(適用: G-7・未消化が1件以上ある場合)

**未消化が0件なら、この節を書きません**。

| 未消化のテスト | 未消化の理由 | 実施した代替 | 残存リスク |
| --- | --- | --- | --- |
| | | | |

**残存リスクには、未消化のテストが担っていた検出対象のうち、代替で覆えなかったものを書きます**。理由と残存リスクを別に求めるのは、**代替を実施した事実が、代替で覆えた事実を意味しないため**です。

書くのは**未消化を生じさせた側**です。出荷判定者は記録の存在を確認します。**内容の十分性は判定しません**。

**消化率は、計画の十分性を保証しません**。計画に入らなかった検証対象は、この表に現れません。
