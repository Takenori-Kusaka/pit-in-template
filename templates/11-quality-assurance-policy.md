# 品質保証の方針と受容の基準(層1)

`docs/quality-assurance-policy.md` として置きます。**組織に1つ置き、案件ごと・出荷ごとに書きません**。1ページ・5項目に限ります(標準 第6章 テンプレ11、附属書H H.3)。

組織が「品質を保証する」と主張するための最上位の層です。出荷判定の証跡の集約(`aggregate-evidence`)は、この文書の版・記名・受容しない条件・権限の段階を読み、保証の主張の成立条件1・5・6 を判定します。**この文書が無い、または記名が無い組織では、すべての変更が成立条件1 を満たさず、「品質保証の対象外として出荷した」と出ます**。出荷そのものは止まりません。

- **記名者は、適用範囲の組織単位を最高位で指揮し管理する者**(この単位のトップマネジメント)です。品質保証部門は起案してよいが、記名者にしない。**記名と連署に AI の名義を受け付けません**(AI が起案しても、記名の欄は空欄のまま人へ渡す)
- 記名者は3つの権限((ア) 単位の予算と要員の配置 (イ) 単位の構成員の評価の方針 (ウ) 保証の相手への出荷を止める権限)を持つ者です。持たない権限は「連署者: <氏名(役職)>」(連署を得る)か「上申先とする」(項目5 の上申先をその権限を持つ者にする)と書きます。**どれでもない権限が1つでもあれば、この文書は有効になりません**
- **記名者を、適用範囲の案件の事業決裁者と同一人物にしません**。同一の場合は、保証の開示の項目1 にその旨が出ます(逸脱。1名・3名未満の体制など)
- 全社の品質マネジメントシステムがある組織では、全社の品質方針の下位文書として位置づけ、全社の品質保証部門が整合を確認した者と確認日を冒頭に書きます。職務権限規程などで権限の委譲を受けた者が記名するときは、委譲の根拠を書きます
- 改めるのは、体制の変化点、事業の変化点、外枠の変化(法令の改正、契約の変更、規格の改版)のときだけです。周期的な見直しの文書を置きません。改めたら版を上げ、各案件の D-0 冒頭の版を更新します(体制の変化点に数える)
- 既存の品質マネジメントシステムを持つ組織は、品質方針とリスクの基準の文書へ5項目を加える形で満たしてよい。その場合も、この置き場へ、版と記名と5項目を写した文書を置きます(機械が読むため)
- 1名の組織では、記名者は本人です。本人が記名し、保証の開示に「方針を定めた者と受容する者が同一である」と出ます。組織として品質を保証すると主張するには、外部の確認者と、外部の受容者を置きます

## 1. 保証の相手と範囲の方針

| 項目 | 記載 |
| --- | --- |
| 組織として品質を保証する対象 | <製品・事業ステージ・利用者への露出。例: S1 以降の顧客向け製品> |
| 組織として品質を保証しない対象 | <例: S0 探索の案件。機械学習の振る舞いを持つ製品の、その振る舞い(本標準の範囲外)> |
| 検出能力の未測定を許容する期間 | <例: 90日 / 出荷 2 回。この期間を超えて未測定が続く出荷は、成立条件5 を満たさない。未記入は「許容しない」として扱われる。この期間を見るのは成立条件5 だけであり、項目2 の印 `[未測定]` には及ばない> |
| 評価の方針 | 停止の申し立て・差し戻し・異議・所見・権限の一時制限の発動の件数を、個人と組織の評価の減点に使わない。AI の利用量・PR の本数・リードタイムを、人の目標値にしない |

## 2. 受容しない条件

否定リストです。当たる事実が保証の開示にある出荷は、出荷判定(G-7)で差し戻されます。

行頭に `[語]` の印を付けた条件は、出荷判定の証跡の集約が保証の開示の値と機械で照合します。印の無い条件は、機械では照合しません(出荷判定者が開示と突合する)。使える印は次のとおりです。

| 印 | 当たる事実 |
| --- | --- |
| `[R1未確認]` | 独立した人の確認を経ていない R1 の変更がある |
| `[未達ゲート]` | 構成上の未達のゲートがある |
| `[逸脱]` | 代償措置つきの逸脱・兼務の逸脱がある |
| `[未回収の例外]` | 技術負債台帳に未返却の例外承認の行がある |
| `[未測定]` | 検出能力が未測定である(人の層・AI の層のいずれか)。**項目1 の許容期間に依らず、未測定の最初の出荷から当たる**。期間の猶予を与える組織は、この印を付けない(期間は成立条件5 が見る)。条件の文に期間の表現を書いても機械は読まない(量を伴う期間の表現(「出荷 2 回」「90 日」)があり、「依らず」「即時」とも書かれていない文には、出荷の集約が「人が確かめる」の注記を出す。出荷は止めない) |
| `[未測定:人]` / `[未測定:AI]` | `[未測定]` のうち、照合する層を人の層だけ、または AI の層だけに限る。AI の層を検出の層に数えない組織は `[未測定:人]` を使う(モデルの世代交代で AI の層の値が失効しても、この条件は当たらない)。許容期間との関係は `[未測定]` と同じ |
| `[台帳:<語>]` | 技術負債台帳の未返却の行(例外・未解決・負債)の内容に `<語>` を含む行がある。例: `[台帳:個人データ]` |

- <例: [台帳:安全] 安全に関わる未達の残存リスク>
- <例: [台帳:法令] 法令・契約の要求事項に当たる未達>
- <例: [台帳:個人データ] 個人データの取り扱いに当たる未達>
- <例: [R1未確認] 独立した人の確認を経ていない R1 の変更>
- <例: 確約範囲(SC-M)に当たる未解決の欠陥(印なし。出荷判定者が突合する)>

`<例: …>` の行は記入として扱いません。記名者が条件を決めて書き換えます。条件が1件も無い文書は、記名があっても有効になりません(成立条件1 を満たさない)。

## 4. 受容の権限の段階

受容者は**役割名**で書きます(`事業決裁者` `出荷判定者` `価値責任者` `技術判断者` `独立レビュア` `AI運用担当者` `AI維持管理者` など、D-0 の席の名前)。席の名前で書いた行は、機械が記名した者とその席の責任者を照合します。席に当たらない役割(事業部長など)の行は、記名が自然人であることだけを確かめます。

| 受容の対象 | 受容できる水準 | 受容者(役割) | 受容の期限 |
| --- | --- | --- | --- |
| 品質の残存リスク(保証の開示の項目5) | <例: R2・R3 の未達> | <例: 事業決裁者> | — |
| 品質の残存リスク(上の水準を超えるもの) | | <例: 事業部長> | — |
| 品質保証の対象外として出荷すること | | | — |
| (必須)組織継続の状態: 代替の無い依存先 | | | <期限つき> |
| (必須)組織継続の状態: 退出を試していない依存先 | | | <期限つき> |
| (必須)組織継続の状態: 縮退の能力を確かめていない業務 | | | <期限つき> |
| (必須)組織継続の状態: 後継のいない判断の席、理解の保持者が1名以下のコア機能 | | | <期限つき> |
| (必須)停止の申し立ての解除(第7章 7.11) | | | — |
| (必須)AI の利用の拡大(自律レベルの引き上げ、委任の範囲の登録) | | | — |
| (必須)AI の利用の縮小・停止(組織全体) | | | — |
| (必須)有事の決定: 重大事故(停止・切替・顧客説明) | | | — |
| (必須)有事の決定: 情報漏えい(停止・切替・顧客説明) | | | — |
| (必須)有事の決定: 契約変更(停止・切替・顧客説明) | | | — |
| (必須)有事の決定: 規制変更(停止・切替・顧客説明) | | | — |

- **(必須)の行の受容者が1つでも空欄の層1 は有効になりません**(成立条件1 を満たさない。テンプレ11 の要求事項6)。行を消しても同じです
- **「AI の利用の拡大」の行の「受容できる水準」を `認めない` で始めると、委任の登録を構成で拒否します**(構成の錠。`/process-change` の種別 mode・performer が、席を委任にする・委任の規則と変更種別を足す・規則を承認する入力を受け付けない。出荷の集約は、錠のある層1 のもとで構成に委任の登録が残っていれば記載の欠落にする)。機械が読むのは欄の先頭が `認めない` であることだけで、文の残りは読みません。「本版では認めない」のように語を含むだけの欄は錠になりません(出荷の集約と `/pit` が「人が確かめる」と出す)。委任を認めるには、記名者がこの欄を改めて版を上げます(体制の変化点)。錠を掛けない組織では、委任の登録はこの行の受容者の受容を要します
- 段階は決裁権限の表(標準 第3章 3.8.2)に接続します。新しい権限体系を作りません
- 組織継続の状態の受容は期限つきです。受容の記録は各案件の D-0 節15 に書きます。期限を過ぎた受容は、保証の開示で記載の欠落になります
- 有事の決定者は、D-0 節7 の有事の事象の表から引かれます。同じ事象に別の決定者を書きません

### 確認の周期と後継

1回の記録が永続しないための表です。間隔・頻度・周期を過ぎた記録は失効し、表示は「退出を試していない」「未確認」「後継不在」へ戻ります。**値の初期値を本標準は定めません**(値を支える測定が無いため)。組織が決めて書きます。

| 項目 | 値 | 空欄の場合の扱い |
| --- | --- | --- |
| 演習(開発避難訓練の類型E・F)の頻度 | <例: 半年に1回> | 保証の開示の項目7 に「演習の頻度を定めていない」と表示する |
| 退出の予行の間隔(第3章 3.12.3) | <例: 12か月> | 予行の記録があっても「退出を試していない」と表示する |
| 縮退の実測の頻度(第3章 3.12.5) | <例: 12か月> | 実測があっても処理できる量を「未確認」と表示する |
| AI を使わない力量の確認の周期(第3章 3.4.3) | <例: 12か月> | 確認の有効性を判定できないため、後継候補を確認済みに数えず、理解の保持者も数えない |
| 判断の席ごとの後継候補の最低数 | <価値責任者: N / 技術判断者: N / 独立レビュア: N / QA: N> | すべての判断の席を後継不在と表示する |
| 育成の担当(役割) | <例: 技術判断者の席の責任者> | 後継不在の受容を更新できない |
| 人の層の再測定の契機(附属書H H.6 項目6) | <例: 席の責任者の交代 / 見つける者の離脱 / なし> | 測定した見つける者の全員が名簿(体制の内)にも独立レビュアの席にも居なくなったときだけ失効し、席の責任者の交代は注記にとどめる |

- 間隔は「90日」「12か月」「半年に1回」「四半期」「毎年」の形で書く。読めない値は空欄として扱われる
- 空欄は層1 を無効にしない。組織継続の側の状態を不利な側へ倒して表示する(要求事項7)
- 「人の層の再測定の契機」は、人の層の検出率(目隠しの欠陥注入)を測定した見つける者が席を離れたときに、値を失効させる条件を定める。「席の責任者の交代」と書けば、独立レビュアの席の責任者が測定した見つける者に含まれなくなった時点で失効する。「見つける者の離脱」と書けば、測定した見つける者の1人でも名簿(体制の内)から離れた時点で失効する。両方を書いてよい。空欄のときは、全員が離れたときだけ失効し、一部が離れたときは残る者の指摘の和集合で値を読み直す(出荷の証跡の集約の項目6)

## 読み方

- 項目2 は、トップマネジメントが事前に定める客観的な条件である。出荷判定者は、当たる事実が保証の開示に無いことを突合する。値の良否を判断させるものではない
- 項目4 の受容者は、G-8 で受容を記名する者の範囲を定める。段階を超える受容は、項目5 の上申先へ届く
- 受容の基準の値(件数・比率)を、本標準は定めない。組織が定める
- **社内の受容は、外部への責任を限定しない**
