## 成果物の適否の確認の基準

契約が、成果物の適否を確認する行為(検収など)を定める場合、確認の基準は**受入基準への適合**に限ります。生成の手段は問いません(標準 第8章 軸D)。

契約上の確認行為が無い契約でも、成果物の適否を対象としない契約でも、独立レビュー(G-6)と出荷判定(G-7)は成立します。受入基準への適合は、この2つの判定で確かめます。

- [ ] 受入基準ごとに、違反すると失敗するテストが存在する

判定記録・技術負債台帳・運用引き継ぎ文書の揃いを、確認の基準に加えません。受入基準でない項目を並べると、契約上の確認の基準を広げて読まれます。提出を求める記録は第10節に書きます。

## 1. AI 利用の開示

| 項目 | 合意 |
| --- | --- |
| AI の利用 | 有 / 無 |
| 利用する工程 | 要件 / 設計 / 実装 / テスト / 文書 |
| 用いるモデルまたはサービス | |
| 生成部分の識別方法 | <例: コミットのトレーラ、変更単位の記録> |
| 記録する項目 | モデルの識別子と版 / 指示資産の版 / 実行の識別子 |
| 記録の保持期間 | |
| 提出の様式 | |

AI を利用する場合、成果物のどの部分が生成されたかを識別できる状態で納品します。

**指示の全文は保存しません**。分量が増え続けること、秘匿情報の混入を検査する対象が増えること、全文があっても生成は再現しないことによります。

**「記録しているため再現できる」と説明してはなりません**。説明できるのは条件の特定までです。

## 2. 測定する指標

**定義を添付しない提示は受け取りません**。同じ名前の指標でも、定義が違えば比較できません。

| 指標 | 定義 | 観測窓 | 母数の下限 | 閾値 |
| --- | --- | --- | --- | --- |
| | | | | |

母数の下限を空にしないでください。件数の少ない期間の値は、閾値の判定に使えません。

## 3. 閾値を超過した場合の措置

| 段階 | 条件 | 措置 |
| --- | --- | --- |
| 1 | 観測窓で閾値を超過した | 原因の報告 |
| 2 | 2期連続で超過した | 是正計画の提出(第4節) |
| 3 | 是正計画の期限内に改善しない | 契約に定める措置 |

## 4. 是正計画の記載事項

是正計画には、発動の根拠となった観測値・原因の分析・是正の措置と実施の期限・**有効性を確認する方法と時期**・実施の記録を書きます。

## 7. 知財の扱い

| 項目 | 合意 |
| --- | --- |
| 依存関係のライセンス検査 | 許可リスト方式。**合否条件とする** |
| 生成物と既存著作物の類似検知 | **合否条件にしない**。実施と記録を判定の対象とする |
| 事業者の知財補償 | 検査を省略する根拠にしない |
| 結果責任を負う者 | <成果物の知財潔白性について責任を負う当事者> |

類似検知を合否条件にすると、「検出されなかった」が「潔白である」という記録として残ります。学習データに含まれていれば利用者が認識していなくても依拠性が推認されうるため、この記録は紛争時の防御になりません。

## 8. 保証の開示と委任の適用

| 項目 | 合意 |
| --- | --- |
| 納品ごとの保証の開示 | 提出する(標準 附属書H H.6 の7項目)。未達・未測定は値として記載する |
| 項目6(検出能力)の示し方 | 測定している事実・測定時点・推移の向き。検出率の値は記載しない |
| 記載が欠落した場合の措置 | <受領の保留、再提出の期限> |
| 委任の適用(標準 第5章 5.5.4) | 適用する / 適用しない |
| 委任する変更種別と、該当を判定する規則の所在 | <適用する場合のみ。合意した種別に限る> |

保証の開示は判定の手がかりであり、品質の保証ではありません。委任の適用に合意が無い場合、人の事前確認を経ていない変更を納品へ含めません。

## 9. 判定の置き先と結果の受け渡し

締結時に決めて記録します(標準 第8章 軸D、第6章 テンプレ8 第9項)。

| 項目 | 合意 |
| --- | --- |
| 技術設計(G-3)の判定を置く組織 | 発注側 / 受注側 |
| 独立レビュー(G-6)の判定を置く組織 | 発注側 / 受注側 |
| 判定の結果を受け取る者(発注側) | <席と氏名。受注側に置く判定が無い場合は「該当なし」> |
| 判定の結果を受け取る者(受注側) | <席と氏名。作成を担う本人と同じ場合は、その旨> |
| G-2・G-8 と契約上の確認行為の対応づけ | G-2: <対応づける確認行為の名称 / 対応づけない>。G-8: <同> |
| 強制層を所有する組織(リポジトリと CI の管理権限を持つ側) | 発注側 / 受注側 |
| AI維持管理者の席の責任者と、その者の属する組織 | <氏名と組織> |
| 誘導層と再利用層を保守する組織 | 発注側 / 受注側 / 双方(分担) |
| 強制層を緩める変更への、所有する組織の同意の形 | 事前の同意 / 事後の提出(同意する者: <所有する組織が指名した者>)。AI維持管理者の席の責任者が所有する組織に属する場合は「該当なし(同じ組織)」 |

- 企画承認(G-1)・要件合意(G-2)・仕様承認(G-4)・出荷判定(G-7)・リリース決裁(G-8)の判定は、発注側に置きます。自動検査(G-5)は置き先を持たず、強制層を所有する組織の CI で判定します。この表では選びません
- 受注側が受注の可否を決める社内の決裁は、標準のゲートではありません
- 独立レビュー(G-6)は、置いた側が読解の帯域を負います
- レビューの実施は、成果物の完成の承認ではありません
- 判定の結果は、通過または差し戻しと、その理由です。差し戻しは、満たさない判定基準の項目番号で示します
- 判定の結果を相手の組織へ渡したら、判定記録の「結果の受け渡し」へ、渡した先と日時を書きます。受け取った側の受領の記名は求めません
- 対応づけない場合も、空欄にせず「対応づけない」と書きます
- 判定の結果を渡す経路の中身、宛先とする席、契約の類型ごとの責任の配分を、標準は定めません。当事者が決めます

強制層は、ルールセットとブランチ保護、必須チェック、CI のワークフロー、ゲートの検査のスクリプト、検査の閾値と除外設定、エージェントの権限設定、実行前フックです。リポジトリと CI を所有する側だけが、分離が成立していることを検証できます。所有しない側は、提出された記録を受け取れるだけです。**監視によって分離を担保する構成を採りません。**

- 強制層の変更は、AI維持管理者が承認します。AI維持管理者の席の責任者が強制層を所有する組織に属さない場合は、緩める向きの変更(遮断の解除・閾値の緩和・強制層の縮小)に、所有する組織が指名した者の同意の記録も要します。同意の形の欄を空欄にしません
- 発注側の要求は、受入基準・出荷できない状態・強制層の検査として書きます。誘導層(`CLAUDE.md`・スキル)だけに書いた要求は、要求として扱いません

第5節の「提示を求める記録」(監査で見る記録)とは別に、納品とともに提出する記録を書きます。**提出だけを義務にすると、提出の形式を満たす動機だけが働きます**。不一致の措置が抜けやすい箇所です。

## 11. 受け入れの速度

受注側の検証が不十分な場合、その分は発注側の判定帯域へ移ります。帯域は増えません。

| 項目 | 合意 |
| --- | --- |
| 期間あたりに受け入れる変更単位の数 | |
| レビュアあたりの同時保有数の上限 | |
| 上限に達したときの扱い | 受け入れを止める。**判定を省略して受け入れない** |

上限へ繰り返し到達する場合、原因は受注側の検証の水準にあります。受け入れ速度ではなく、そちらを是正の対象とします。

## 12. 計算資源の費用

エージェントの実行費用は、変更の量ではなく試行の回数で増えます。自己修復のループが収束しない場合、費用は成果物を伴わずに増加します。

| 項目 | 合意 |
| --- | --- |
| 費用の負担者 | **実行環境を所有する側** |
| 期間あたりの上限額と、上限へ到達した場合の措置 | <上限額>。到達した場合は実行を強制停止する。超過を検知して報告する構成を採らない |
| 上限を超える実行を許可する手続と、その承認者 | |

所有していない側へ負担させた場合、費用を抑える操作はその側にありません。

## 13. 発注側に読解の帯域がない場合

発注側が AI 生成コードを読み解けない状態で、受注側の検証の正しさを確かめる方法はありません。選択肢は3つです。

| 項目 | 合意 |
| --- | --- |
| 選んだ選択肢 | 発注側へ読解の担い手を置く / 読解を、発注側と受注側のどちらでもない組織へ委託する(当該案件の開発に関与していない者)/ 対象を、読解しなくても受け入れられる範囲へ限定する(1つ以上) |

**いずれも選ばない状態を認めません**。選ばない場合、成立しているのは契約上の確認行為の外形だけです。
