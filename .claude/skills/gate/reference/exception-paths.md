# 基準を満たさないまま進めるときの経路

`CLAUDE.md`「基準を満たさないまま進めるとき」の詳細です。台帳の行の書き方は `.claude/skills/artifact/artifacts/03-debt-ledger.md`、G-6 を経ない変更の例外承認は `../gates/G-6.md` にあります。

**3つの経路があります。どれを使うかを、その場の判断で決めません。**

| 事象 | 経路 | 台帳の区分 |
| --- | --- | --- |
| **当該ゲートの判定基準を満たさないまま進める** | 例外承認 | 例外 |
| **前提が劣化し、判断の土台が変わった** | 前提の受容 | — |
| **判定基準には含まれないが、放置できない事項が残った** | 未解決事項 | 未解決 |

**例外承認と前提の受容は、事後と事前で分かれます**。例外承認は成果物が存在する時点で基準の不充足を認める手続であり、前提の受容は判断の土台にした前提が崩れたことを認める手続です。

いずれも**技術負債台帳(テンプレ3)へ区分つきで記録します**。区分を分けるのは、**ゲートを止めるべきものと止めないものを見分けるため**です。

## 例外承認の「対象」は、変更か、ゲートの判定か

| 例外を適用するもの | 台帳の「対象」 | 照合 |
| --- | --- | --- |
| 変更(PR・コミット)。例: G-6 を経ない変更、変更規模の上限を超える PR | `PR #12`、コミットの識別子(先頭7桁以上) | G-5 の `pr-rules`(変更規模)と、出荷判定の証跡の集約が、その変更に対応づける |
| ゲートの判定。例: 前提の台帳が無いまま G-1 を判定する、G-2 の基準の一部を満たさないまま G-2 を判定する | `G-<N> <判定記録の対象>`。例: `G-1 P-001`、`G-2 F-001` | 出荷判定の証跡の集約が、変更の行と分けて記入の成立を確かめる。変更へは対応づけない |

- ゲートの判定が対象の例外は、PR の番号を先に取る必要が無い。判定記録の「対象」と同じ値を書く
- 1行が1つのゲートの1つの対象を指す。「F-001 の出荷まで」のような範囲を対象にしない。ゲートごとに行と承認を置く
- 前提の台帳(`docs/assumptions.md`)が無いことは、全ゲートの共通条件を欠く状態である。例外承認を重ねるより先に、台帳を作る(`.claude/skills/artifact/artifacts/10-assumption-ledger.md` に、前提の定義と観測の手がかりの要約がある)
- 承認した者は D-0 節3「例外承認」の決定者。その行が空欄なら、例外承認を記録する前に、D-0 節3 を人が手で書く(`/process-change` の種別は無い。`.claude/skills/artifact/artifacts/00-d0-governance.md`)

**未解決事項は、ゲートの通過を妨げません**。判定は「通過」「差し戻し」の2値のままで、条件付き通過という値はありません。期限までに解消しない場合、例外承認か前提の受容のいずれへ送るかを判定します。

**次工程の材料が未完成であることを、当該ゲートの差し戻し理由にしてはなりません**。それは未解決事項として台帳へ置き、当該ゲートは判定基準だけで判定します。
