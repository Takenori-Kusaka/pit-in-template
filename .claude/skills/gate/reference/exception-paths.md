# 基準を満たさないまま進めるときの経路

`CLAUDE.md`「基準を満たさないまま進めるとき」の詳細です。台帳の行の書き方は `.claude/skills/artifact/artifacts/03-debt-ledger.md`、G-6 を経ない変更の例外承認は `../gates/G-6.md` にあります。

**3つの経路があります。どれを使うかを、その場の判断で決めません。**

| 事象 | 経路 | 台帳の区分 |
| --- | --- | --- |
| **当該ゲートの判定基準を満たさないまま進める** | 例外承認 | 例外 |
| **前提が劣化し、判断の土台が変わった** | 前提の受容 | — |
| **判定基準には含まれないが、放置できない事項が残った** | 未解決事項 | 未解決 |

**例外承認と前提の受容は、事後と事前で分かれます**。例外承認は成果物が存在する時点で基準の不充足を認める手続であり、前提の受容は判断の土台にした前提が崩れたことを認める手続です。

いずれも**技術負債台帳(テンプレ3)へ区分つきで記録します**。区分を分けるのは、**ゲートを止めるべきものと止めないものを見分けるため**です。

## 例外承認の「対象」は、変更か、ゲートの判定か

| 例外を適用するもの | 台帳の「対象」 | 照合 |
| --- | --- | --- |
| 変更(PR・コミット)。例: G-6 を経ない変更(規模の基準値の超過は、例外承認でなく PR の「規模の確認」で扱う) | `PR #12`、コミットの識別子(先頭7桁以上) | 出荷判定の証跡の集約が、その変更に対応づける(G-5 の `pr-rules` は、基底に既にある規模の超過の行を有効として読む) |
| ゲートの判定。例: 前提の台帳が無いまま G-1 を判定する、G-2 の基準の一部を満たさないまま G-2 を判定する | `G-<N> <判定記録の対象>`。例: `G-1 P-001`、`G-2 F-001` | 出荷判定の証跡の集約が、変更の行と分けて記入の成立を確かめる。変更へは対応づけない。ただし対象が `G-5 PR-<番号>` で内容の先頭が印 `変異試験の閾値割れ` の行(下の「段 mutation の閾値割れ」)は、集約が段と同じ読みで見分け、対象の PR の写しの宣言行のレビューで帰属を数える。ほかの G-5 の行は常に欠落になる |
| G-5 の段 mutation の閾値割れ(附属書F F.6。閾値を定めた場合に限る。段が空・閾値未設定・規制要件の段の不合格・コマンドの終了コードが 0 でない場合・手動の実行には使えない) | `G-5 PR-<番号>`(対象の PR の番号。`PR #12` の形は書かない。変更の行と読まれ、別の例外承認として効きうる)。内容の先頭は印 `変異試験の閾値割れ` | 段 mutation が台帳の行を読み、承認した者本人が対象の PR の上で宣言行 `例外承認: D-NNN` のレビューを出していれば、閾値割れを受けて通す(下の「段 mutation の閾値割れを台帳の行で受ける」) |

- ゲートの判定が対象の例外は、PR の番号を先に取る必要が無い。判定記録の「対象」と同じ値を書く
- 1行が1つのゲートの1つの対象を指す。「F-001 の出荷まで」のような範囲を対象にしない。ゲートごとに行と承認を置く
- 前提の台帳(`docs/assumptions.md`)が無いことは、全ゲートの共通条件を欠く状態である。例外承認を重ねるより先に、台帳を作る(`.claude/skills/artifact/artifacts/10-assumption-ledger.md` に、前提の定義と観測の手がかりの要約がある)
- 承認した者は D-0 節3「例外承認」の決定者。その行が空欄なら、例外承認を記録する前に、D-0 節3 を人が手で書く(`/process-change` の種別は無い。`.claude/skills/artifact/artifacts/00-d0-governance.md`)

## 段 mutation の閾値割れを台帳の行で受ける(標準 第7章 7.3・附属書F F.6。ADR-0243)

段 mutation が走り、閾値(`ci.mutationThreshold`)を下回るスコアを出したときだけ、次の行で受けて通せます(適用: R1 の変更の PR と案件の条件の PR の両方)。

- 台帳の行: 区分「例外」、対象 `G-5 PR-<この PR の番号>`、内容の先頭が印 `変異試験の閾値割れ`(強調の記号は読み飛ばす)、状態「未返却」、返却の目安が期限内の日付(YYYY-MM-DD)、承認した者・受容した理由の記入。承認した者は名簿の人で、AI の名義と PR の作成者と作成を指示した者は書けない
- 帰属: 承認した者本人が、**この PR の上で**宣言行 `例外承認: D-NNN` のレビューを出し、そのレビューの対象のコミットが PR の先頭と一致する。コミットを足すと承認は効かなくなり、出し直す。レビューを出した後は gate-g5 の「失敗したジョブの再実行」で再評価する
- **承認した者は、宣言行のレビューを出す前に、段の出力のスコアを読む。受容した理由の欄にスコアを書く**。印にスコアの下限は書かない(機械はスコアの妥当性を見ない。受けたスコアが妥当かは承認した者と G-6 の判定者が確かめる)
- 基底(既定ブランチ)にある行は、基底の内容で読む。PR の中で期限や状態を書き換えても効かない。PR の中で足した行は、上の帰属を満たしたときだけ数える
- **作成を指示した者を `@` で書いた PR では、閾値割れを台帳の行で受けられない**。段は `@` のアカウントを識別子で確かめられず、指示者の排除が抜け道になるため受けない側に倒れる。作成を指示した者を名簿の記載の名で書き直し、失敗したジョブを再実行する(本文の編集で再評価される)。基底の台帳に先に行を入れても、`@` の指示者は退けられる
- 受けたとき、段は終了コード 0 で、出力に「閾値割れを第7章 7.3 の例外承認 D-NNN で受けた」の1行(スコア・閾値・承認した者・返却の目安)を出す。**G-7 が見るのは行の形(対象・印)と帰属・期限だけ**で、段がその行で受けた事実は、この出力(ジョブのログ。保持の期限がある)と承認した者の宣言行に頼る
- 返却の目安に上限は無い(遠い日付を書ける)。機械は日付が期限内かだけを見る。上限が無い点は既存の例外の行と同じで、回収の中身は G-6 の判定者と出荷判定者が確かめる
- 閾値割れの行だけは、出荷へ持ち越せない。行が G-7 で成立するのは対象の PR を含む出荷だけで、以後の出荷では、状態を返却済みにするか行を取り下げるまで、欠落として G-7 を止める
- **道具の側で閾値を終了コードへ結ぶ(Stryker の `thresholds.break` を `PIT_IN_MUTATION_THRESHOLD` に合わせる等)と、閾値割れが終了コード 1 になり、受けられない**。受けたい場合は、閾値の比較を段に任せる(道具は終了コード 0 で行を出す)
- この 3 点は受けない: 段が空のままの通過(7.4 が禁じる、G-5 の判定を実施しないままの進行)・閾値が無い構成での閾値割れ(閾値割れが無い)・規制要件の段の不合格(ADR-0224 決定7)
- 基底(既定ブランチ。push では直前のコミット)の構成や台帳を読む点を取り出せない場合も受けない(基底に `process.config.json` が無い、新しいブランチの最初の push など)。作業ツリーの内容へは倒さない

## 例外承認の対象と期限(標準 第7章 7.3)

- **対象は、ゲートの判定基準と、本標準の条項が 7.3 を名指した事項に限る**。席の兼務の禁止、文脈の分離、人の名簿、認証情報の分離などの構成の条件は、例外承認の対象にしない。本標準の条項が 7.3 を名指した構成の条件は、第4章 G-8「配備の統制と資格情報の置き場」である。構成の条件を満たさない状態は、未達・逸脱・列挙に無い離脱として扱う。条項が例外を認めないと定めた基準には、7.3 を使わない
- G-8「配備の統制と資格情報の置き場」を満たせない場合(手段が無い・使わないと決めた)は、構成の条件のうち例外承認で受けられる唯一の事項である。台帳の行の「対象」は、**配備のワークフローの所在と配備先(成果物)**を書く(例: `.github/workflows/<配備のワークフロー>.yml` と、配備先の識別)。理由には、揃えていない形((a)(b) か (c))を書く。回収は、(a)(b) と (c) を揃えること、または配備先をリポジトリの外へ移すこと
- **例外承認は、ゲートの未達を解かない**(G-6)
- **安全重要度の判定の記録と判定者の記名は、7.3 の対象にしない**。G-1 の前提条件であり、欠けた案件は G-1 の審議を開始しない。判定した区分を下げるのは第8章 軸E による(ADR-0153 決定1)
- **G-4 の判定・G-5 の判定・認証・認可・データ保全の検証(7.4 が後回しを禁じた対象)を、行わないまま進めるために 7.3 を使わない**。期日を理由とするかを問わない。台帳の対象が変更の行でも同じ。この用途の行は例外承認の成立を示さず、記録の欠落になる。行った判定・検証で個々の基準を満たさない場合は 7.3 を使える(例外を認めないと定めた基準を除く)。他の機能仕様・判定の記録があっても、当該を行ったことにならない(ADR-0153 決定2)。出荷の証跡の集約は、対象を `G-4 <機能 ID>` とした行のうち当該の G-4 の判定記録が無い行と、対象を `G-5 <対象>` とした行を、成立させない
- **回収の期限を過ぎた例外承認は、期限の翌日から効力を失い、記録の欠落になる**。状態が「未返却」のまま期限を過ぎた行も、状態が「失効」の行も同じ。回収して状態を「返却済み」にするまで、出荷の証跡の集約が欠落として出す。欠落が残る間は、適合の主張を述べられず、G-7 は差し戻しになる
- **延長は、同じ行の期限を書き換えずに、新しい行で承認し直す**。権限を持つ者が 7.3 の要求事項を満たして新しい行を書き、元の行にその行の識別(D-NNN)を書く。期限の書き換えは承認のし直しとして扱わない。AI は承認し直さない(承認した者は人)
- **区分「類似検知」の行の期限の延長も同じ形で行う**。区分「例外」の新しい行を書き、その「対象」に類似検知の行の識別(D-NNN)を書く。期限の書き換えは延長として扱わない。出荷の証跡の集約は、範囲の始点より後の日付への書き換えを記録の欠落にする(IMPL-0787)。返却の目安を早める書き換えは欠落にしない
- 例外承認は逸脱ではない。範囲で用いた件数は、適用の表明と適合の主張に併記する(第1章 1.10.2)

**未解決事項は、ゲートの通過を妨げません**。判定は「通過」「差し戻し」の2値のままで、条件付き通過という値はありません。期限までに解消しない場合、例外承認か前提の受容のいずれへ送るかを判定します。

**次工程の材料が未完成であることを、当該ゲートの差し戻し理由にしてはなりません**。それは未解決事項として台帳へ置き、当該ゲートは判定基準だけで判定します。 <!-- 根拠: 標準 第4章「判定の範囲」 -->

## ファストトラック(7.4)の行の印

ファストトラックの行は、区分「例外」で、内容の先頭を `ファストトラック(短縮: <ゲート>)` とする(様式 03)。G-5 は、括弧の中が G-4・G-5・認証・認可・データ保全を名指す行と、未回収の印の行がある間の新しい印の行を拒む。印の無い行は見分けられない。事後レビューと権限の停止は人が行う。
