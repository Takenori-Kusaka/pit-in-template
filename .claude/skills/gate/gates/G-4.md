# G-4 機能仕様承認

- 判定者の席: 価値責任者(または委譲先)。期限: 24時間
- 判定基準の所在: 標準 第4章「G-4 機能仕様承認」(判定基準1〜5、範囲内外の判定を機械が行わない理由、範囲外と判定した場合)と「タスクの分割基準」。知識ベースの ID は `g-spec-cycle`
- 判定の対象: 機能仕様書 `specs/F-NNN/spec.md` と実装計画 `specs/F-NNN/plan.md`(補助ファイル: `.claude/skills/artifact/artifacts/01-feature-spec.md`・`07-implementation-plan.md`)
- どの事業ステージでも省略できない

## 材料の集め方

1. `node scripts/gate/spec-lint.mjs specs/F-NNN` を実行する(基準1)
2. 判定基準ごとに材料を並べる
   - 基準1: 受入基準の形式(G-2 と同じ形式の確認)
   - 基準2: 実装計画のタスクの表。各タスクが1つのレビュー単位か、どの受入基準に対応するか
   - 基準3: コア / 非コアの指定の欄
   - 基準4: 各タスクの規模の見込みと、構成の上限(`process.config.json` の `task`)。基準値を超える見込みのタスクは、関心事が1つであること(行数に合わせて細切れにしていないこと)を確かめる。超過は失敗にならず、PR の「規模の確認」と区分の下限 R2 で扱う(例外承認は要さない)。関心事が混ざっていれば分け直す
   - 基準5: スコープの層の判定欄(SC-M / SC-P / SC-B / 範囲外)。**空欄なら判定を始めない**。AI は判定の草案を示してよいが、記入は判定者
3. 前提の台帳の、関係する前提の行を示す

## 判定記録の書き方

- 受け皿: 仕様・実装計画が PR として存在する場合は、**判定者本人のレビューの本文**。1 行目に宣言行 `G-4: 通過` または `G-4: 差し戻し / 基準 N / 期限 YYYY-MM-DD`、続けて「確認した項目」を基準の項目番号で書く。状態は問わない(判定者が PR の作成者本人なら COMMENT で提出する。2026-10-23 の実機確認済み)。雛形と条件は `reference/recording.md`「受け皿が承認レビューのゲート」。仕様が PR として存在しない場合は様式(後退経路)
- この承認を G-6 の独立した人の確認に数えない(受入基準の確定であり、別の人による確認ではない。ADR-0060)
- 対象: 機能 ID と、確定した受入基準の版を「/」で区切って書く。版はコミットの識別子(例: `F-012 / 1a2b3c4`)または仕様の PR の番号(例: `F-012 / PR #34`。標準 第4章 G-2)。PR の番号で書いた場合、マージ後のコミットの識別子は機械が写しから併記する。`next.mjs` は「対象」に機能 ID を含む通過の記録(写しの宣言行、または様式)を読んで、実装の段階へ進める
- レビューで判定した場合、様式は置かない。`next.mjs` と出荷の証跡の集約は、記録用ブランチ `records` の写し(`records/reviews/pr-<番号>.json`)を読む。仕様が PR として存在しない場合の様式は、記録用ブランチの `records/gates/` へ判定者本人が push する(`reference/recording.md`「様式の届け方」)
- **次工程の材料の未完成を差し戻し理由にしない**。例: テストが未作成であることは G-4 の理由にならない(G-4 は仕様と分解の承認であり、実装の完了を求めない)
- 範囲外と判定した場合は、内側のループを止めず、影響の範囲に応じて経路を分ける(第2章 2.10.8)
- 確定の形態: 席の運用形態とリスク区分による(`reference/recording.md`)

## 機械の検査

```bash
node scripts/gate/spec-lint.mjs specs/F-NNN
node scripts/gate/next.mjs        # 受入基準・タスクの表の記入と、G-4 の記録の有無から段階を出す
```

- G-4 の後の PR では、G-5 の `pr-rules` が、トレーラ `Spec:` の指す仕様とタスクの実在、変更規模の上限を検査する
- 出荷判定の証跡の集約は、トレーラ `Spec: F-NNN` を持つ変更について、その仕様の G-4 の通過の記録が無ければ欠落にする(禁止事項1 の事後の検出)
- 範囲の内外の判断そのものは機械に委ねない(記入の有無だけを見る)
