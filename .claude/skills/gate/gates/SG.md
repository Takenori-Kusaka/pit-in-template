# SG ステージ移行ゲート(SG-0〜SG-2)

- 判定者: ステアリングコミッティ(会議体 B-2)。期限: 会議体の開催周期
- 判定基準の所在: 標準 第2章 2.4「ステージ移行ゲート」、会議体の語彙と期限は第3章 3.7、予算と中止の判断基準は第7章 7.7
- 工程ゲート(G-1〜G-8)とは別の軸。問いは「投資を継続するか、次ステージへ進むか」

| ゲート | 判定の値 | 主な判定基準 |
| --- | --- | --- |
| SG-0 探索完了 | S1 へ移行 / 継続検証 / 中止 | 事業仮説が実証データで支持されている。技術的実現性が確認されている(実装スタックの確定を含む)。次ステージの投資規模と体制が示されている |
| SG-1 価値確立完了 | S2 へ移行 / 継続 / 中止 | 実利用者における価値が実証されている。拡大に耐えるアーキテクチャが確定している。受入部門が要求を自らの言葉で再構成できている |
| SG-2 スケール完了 | 定常運用へ移行 / 改善継続 | 対象利用者層の品質基準を満たしている。運用体制が定常運用として成立している。受容した負債の返却計画が承認されている |

## 材料の集め方

1. D-0 体制図(SG の提出対象)と、`node scripts/gate/check-d0.mjs` の結果
2. 判定基準ごとに、実証データ・判断記録・技術負債台帳・運用引き継ぎ文書の所在を並べる。**実証データの評価を AI が書かない**
3. 次ステージの予算(第7章 7.7 の4区分)の案。予算は SG の判定と同時に確定する
4. 前提の台帳の、関係する前提の行
5. SG-0 で実装スタックが確定していない場合は、そのことを示す(SG-0 の通過後に未確定が残ると未達)。SG-0 の判定基準を増やさない

## 判定記録の書き方

- 様式は `templates/04-gate-record.md`。置き場は `docs/gates/sg<N>-<案件>-<日付>.md`
- 判定の値は、工程ゲートの2値ではなく、上の表の値(会議体の語彙)
- 確定の形態は**人確定に限る**。決断の記録(確認していない事項を空欄・「なし」にしない)と、比較した選択肢(2案以上。採否の理由は人が書く)が必須
- 判定者の欄には、会議体の決定を記録する責任者(人)を書く。AI を書かない

## ステージの変更を構成へ反映する

- 判定の後、ステージの変更は `/process-change`(種別 `axis`、軸B の回答)で反映する。補助ファイル: `.claude/skills/process-change/kinds/axis.md`
- **ステージを前へ戻す変更は、SG の判定記録を要する**。`sgRecord` に、`docs/gates/` 配下の実在する判定記録を書く。D-0 表1「体制と運用形態」の決定者の記名も要する

## 機械の検査

- `/process-change` は、`sgRecord` が `docs/gates/` 配下の実在する記録を指さない入力を拒否する
- 判定の内容(実証データの十分性など)を機械は判定しない
