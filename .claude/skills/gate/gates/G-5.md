# G-5 自動検証(CI)

- 判定者: 機械(即時)。**人の判定記録は作らない**。証跡は CI の結果と `evidence/`
- 判定基準の所在: 標準 第4章「G-5 自動検証 CI」(判定基準1〜8、検査対象が存在しない場合の扱い、知財潔白性、秘匿情報、依存関係の追加)。知識ベースの ID は `g-ci`
- 実装: `.github/workflows/gate-g5.yml`。必須ステータスチェックの名前は `gate-g5`(集約ジョブ)

## 何が検査されるか

| ジョブ | 基準 | 内容 |
| --- | --- | --- |
| `test` | 1・3 | 全テスト、カバレッジの下限(構成の `ci.coverageThreshold`) |
| `static-analysis` | 2 | 静的解析・依存の脆弱性 |
| `spec-lint` | 4 | 受入基準の曖昧語 |
| `ip-clearance` | 5 | 依存関係のライセンス |
| `secret-scan` | 7 | 秘匿情報の混入。**台帳への記録による通過を認めない** |
| `dependency-diff` | 8 | 依存の追加・更新の一覧(合否なし) |
| `contract` | — | 構成と CI・ブランチ保護の整合、変化点の記録の連鎖 |
| `pr-rules` | — | PR 単位の検査(下記)。#286 |

`pr-rules`(`scripts/gate/check-pr.mjs`)が PR で検査するもの:

- トレーラ `Spec: F-NNN / Task-N` が PR の本文の末尾の段落(スカッシュのメッセージのトレーラ)にあり、指す仕様とタスクが実在する。製品のコードを変えない PR と依存の更新の bot の PR は対象外。変更が開発の基盤(設定・ツール・雛形。`check-pr.mjs` の `SETUP_FILES`)だけに収まる PR は `Spec: setup` で通す(初期化の PR など)。製品のコードを含めば `Spec: setup` では通らない
- 変更規模の上限(**基底ブランチの**構成の `task`)。ロックファイル・生成物・空白だけの変更・内容の変わらない名前の変更・文書と記録は数えない。超えたら、**基底ブランチの**台帳にその PR を対象とする有効な例外承認の行がある場合だけ通す(同じ PR で足した行は数えない)
- 閾値・除外設定と製品のコードの同時変更(禁止事項6)。閾値だけの PR と、初回の設定は通す
- 既存のテストの変更(削除・名前の変更・期待値の変更の候補)を一覧にして PR のコメントへ出す。**失敗にはしない**。G-6 の材料

## 手元で確かめる

```bash
node scripts/gate/g5-local.mjs                    # CI と同じ範囲(pr-rules を含めるなら --base origin/main --pr <PR の JSON>)
```

`spec-lint` は引数なしで CI と同じ範囲(機能仕様の置き場 `specs/F-NNN/`)を見る。様式(`templates/`)・判定記録・体制図は対象にしない。手元の結果は CI の代わりにならない。マージを止めるのは必須チェック `gate-g5`。

## G-5 が落ちたとき(AI の担い手がすること)

1. ジョブの出力の `::error::` の行を読み、原因を特定する
2. テストの失敗は、実装を直す。**テストの失敗をテスト側の変更で解消しない**(禁止事項3)。テストの修正を要すると判明したら、自己修正を終えて受入基準へ戻る(`/implement` の手順4)
3. 変更規模の超過は、実装計画へ差し戻すのが既定。分割は関心事で行い、行数に合わせて細切れにしない。超過したままレビューするかは人が決める(例外承認。台帳の行を先に基底へ入れる)
4. 閾値・除外設定の同時変更は、閾値の変更を別の PR に分ける。閾値を緩める向きは `/process-change`(種別 `settings`)と記名を要する
5. トレーラ `Spec:` の不備は、PR の本文の末尾の「トレーラ」の節を直す。**トレーラだけを足して判定を通すことをしない**(指す仕様とタスクが、実際にこの変更の対応である場合に限る)

## 検査の対象が無い場合

実装が無い段階では、テスト・静的解析・カバレッジ・ライセンス・依存の一覧の基準を「対象なし」として記録したうえで通します。基準6(文脈ファイルの形式)と基準7(秘匿情報)には「対象なし」を使いません。実装が始まった後に「対象なし」が出たら、検査の不備です。

## ブランチ保護

- G-5 が落ちた PR のマージを止めるのは、ルールセットの必須チェック(`gate-g5`)。適用は人が行う(`.github/rulesets/README.md`)
- ルールセットを使えないプランでは、止められない。出荷判定の証跡の集約が、gate-g5 の成功を持たない PR を事後に欠落にする(`gates/G-7.md`)

## 判定記録

G-5 の判定記録は作りません。G-7 の突合で、PR ごとの gate-g5 の結果と `evidence/` の証跡を読みます。
