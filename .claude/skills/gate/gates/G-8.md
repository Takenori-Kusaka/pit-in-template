# G-8 リリース決裁

- 判定者の席: 事業決裁者。期限: 48時間
- 判定基準の所在: 標準 第4章「G-8 リリース決裁」(判定基準1・2、残存リスクの受容、出荷判定者の異議、期間ごとの保証の開示)。知識ベースの ID は `g-release`
- 判定の対象: G-7 の通過の記録と、保証の開示に載った残存リスク

## 材料の集め方

1. G-7 の通過の記録があるか(基準1)
2. 保証の開示(G-7 の集約の出力)と、品質レポートの「出荷判定者の異議で検討する事項」を、出荷判定者と事業決裁者へ示す。**AI は開示を要約・評価しない**

## 判定記録の書き方

- 対象: 出荷のタグ(例: `v1.4.0`)
- 確定の形態: **人確定に限る**。協働・委任と書いた決断の記録は無効
- 決断の記録(確認した事項・確認していない事項・判断が変わる条件・受容したリスク・出荷判定者の異議)は必須。「確認していない事項」を空欄・「なし」にしない
- 比較した選択肢(2案以上)を書く。AI は案とリスクの見積を示してよい。**採否の理由は人が書く**
- 技術品質を蒸し返さない。G-8 の差し戻し理由に技術品質を挙げない(G-7 との役割分担)

### 出荷判定者の異議

- 「出荷判定者の異議(リリース決裁 G-8 の記録に限る)」の欄は、**出荷判定者が書く**。異議が無い場合も「異議なし」と書く。**エージェントがこの欄を埋めない**
- 空欄なら記録を完成させない。事業決裁者は、空欄のままでは受容を記名しない
- 保証の開示が次のいずれかに当たる場合は、異議の有無とあわせて**理由**を書く(「異議なし」でも同じ)

| # | 事項 |
| --- | --- |
| 1 | 独立した人の確認を経ていない R1 の変更がある |
| 2 | 検出能力が未測定のまま、連続して出荷している |
| 3 | 独立した人の確認を経ていない変更の件数、または構成上の未達のゲートと逸脱の数が、前回の出荷より増えた(どちらか一方の増加で当たる) |
| 4 | 事後の抜き取りを、作成を指示した本人が行っている |

- 出荷判定者と事業決裁者の席の責任者が同一人物の体制(1〜2名)では、保証の開示の項目1 に「異議を書く者と、残存リスクを受容する者が同一である」と出る。異議の記載と受容の記名は省かない

### 残存リスクの受容

- 事業決裁者は、保証の開示に載った未達・未測定・未回収の例外を読み、受容を「受容したリスク」欄へ記名で残す。異議を受けて受容する場合は、異議の扱いも書く
- 受容できないときは、基準2 を理由に差し戻す。開示されたどの事実を受容できないかを書く

## 記録の後にすること

**G-8 の記録を書いた後に、集約をもう一度実行する**(`ship-evidence` の手動実行。起点に前回のタグ、終点に今回のタグ)。集約は、当該出荷の G-8 の記録の異議の欄が空欄、または事項に当たるのに理由が無い場合を欠落にする。機械が見るのは理由の記載の有無だけで、内容は判定しない。

## 期間ごとの保証の開示(委任で先へ進めた変更)

- 開示: `node scripts/gate/aggregate-evidence.mjs --period-from <起点> --period-to <終点>`(ワークフロー `assurance-period`)
- 受容と異議は、G-8 の判定記録へ残す。「対象」へ期間を起点〜終点の形で書く(例: `委任の期間 2026-09-01〜2026-09-30`)。日付は起点と終点の2つだけ
- 記録の無い期間の開示は記載の欠落。結果が差し戻しの記録は、受容していないものとして扱う。記録を書いた後に、同じ期間で集約し直す

## 機械の検査

- 出荷判定の証跡の集約: 異議の欄の空欄、事項に当たるのに理由が無い記載、期間の記録の有無、判定者の記名と結果
