# G-3 技術設計判断

- 判定者の席: 技術判断者。期限: 48時間
- 判定基準の所在: 標準 第4章「G-3 技術設計判断」(判定基準1〜5、事業影響を金額で定量化しない、記載の検査、事業決裁者が受容を拒否した場合)。知識ベースの ID は `g-tech-design`
- 判定の対象: 判断記録(ADR)`context/decisions/NNNN-*.md`(補助ファイル: `.claude/skills/artifact/artifacts/02-adr.md`。作成は `/adr-write`)
- 受信箱: `state:needs-tech`。技術判断者が開発者とレーンを共有する体制でも、**セッションを分けて**受け取る

## 材料の集め方

判定基準ごとに、ADR の該当する欄の所在を表へ並べます。

- 基準1: 非機能(性能・可用性・セキュリティ)の欄
- 基準2: 恒久層の設計標準(`context/standards/`)との突合。食い違う箇所の一覧
- 基準3: 可逆性の欄(戻せない選択か、戻せなくなるもの)
- 基準4: 比較した代替案の表(最低1つ。不採用の理由)
- 基準5: 事業影響の5項目に空欄が無いこと

機械で確かめてよいのは形式的な欠落だけです。

| 確かめること | 誰が |
| --- | --- |
| 欄が空である | 機械(このテンプレートに実装は無い。記録を起こす者が数え上げる) |
| 「回復に要する時間」が幅でなく単一の値 | 同上 |
| 「顕在化が分かる兆候」が「なし」 | 同上 |
| 前の判断記録と記述が一致している | 同上 |
| 記述の内容が妥当である | 判定者 |

## 判定記録の書き方

- 対象: ADR の番号と機能 ID
- 発生確率と影響度の格付けを掛け合わせた順位づけを、判定の根拠にしない
- R1 に当たる決定は人確定。「比較した選択肢」の欄が必須で、採否の理由は人が書く(AI は案とリスクの見積を示してよい)
- 差し戻しは基準の項目番号で書く

## 事業決裁者が受容を拒否した場合

| 拒否の理由 | 差し戻し先 |
| --- | --- |
| 別の技術的選択で回避しうる | G-3 へ差し戻す(基準4) |
| どの技術的選択でも受容できない | G-2 へ差し戻す |
| 案件の前提が崩れている | 中止の判断へ上程する(第7章 7.7.3) |

「受容できないが進める」を通常の経路として認めません。認めるなら例外承認(`reference/exception-paths.md`)。

## 機械の検査

- ADR の欄の形式的な欠落を検査する仕組みは、このテンプレートに無い(限界)
- 出荷判定の証跡の集約は、判断記録の有無を数える
