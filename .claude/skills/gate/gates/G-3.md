# G-3 技術設計判断

- 判定者の席: 技術判断者。期限: 48時間
- 判定基準の所在: 標準 第4章「G-3 技術設計判断」(判定基準1〜5、事業影響を金額で定量化しない、記載の検査、事業決裁者が受容を拒否した場合)。知識ベースの ID は `g-tech-design`
- 判定の対象: 技術上の選択。範囲は標準 第2章 2.6「判断記録の範囲」
- 判定の材料: 判断記録(ADR)`context/decisions/NNNN-*.md`(補助ファイル: `.claude/skills/artifact/artifacts/02-adr.md`。作成は `/adr-write`)。書式が整っていても、選択が誤っていれば差し戻す
- 判定の証跡: 判定記録(`templates/04-gate-record.md`)。判断記録の内容を再掲せず、番号と版で引く
- 受信箱: `state:needs-tech`。技術判断者が開発者とレーンを共有する体制でも、**セッションを分けて**受け取る

## 材料の集め方

判定基準ごとに、判断記録の該当する欄の所在を表へ並べます。

- 基準1: 判断記録の「非機能への影響」欄(性能・可用性・セキュリティ)
- 基準2: 恒久層(用語集・設計標準・プロダクトの原則 `context/standards/principles.md`)のうち存在するものと、`context/decisions/` に残る判断記録(状態が採用または一部置き換え)との突合。食い違う箇所の一覧。いずれも無い場合は、突合先が無いことを判定記録へ書く
- 基準3: 判断記録の「可逆性」欄(戻せる選択か、戻せなくなるもの)
- 基準4: 比較した代替案の表(最低1つ。不採用の理由)
- 基準5: 事業影響の5項目に空欄が無いこと

機械で確かめてよいのは形式的な欠落だけです。

| 確かめること | 誰が |
| --- | --- |
| 欄が空である | 機械(このテンプレートに実装は無い。判定者が読んで確かめる) |
| 「回復に要する時間」が幅でなく単一の値 | 同上 |
| 「顕在化が分かる兆候」が「なし」 | 同上 |
| 前の判断記録と記述が一致している | 同上 |
| 置き換えの両側の参照(「置き換える決定」欄と、置き換えられた側の状態の行)が一致し、全部の置き換え・廃止が保管領域にある | 機械(`node scripts/gate/check-decisions.mjs`。G-5 の contract ジョブでも走る) |
| 記述の内容が妥当である | 判定者 |

## 判定記録の書き方

- 対象: 機能 ID。「判定した判断記録(G-3 のみ)」の行へ、判断記録の番号と、判定した版のコミットを書く(内容は再掲しない)
- 発生確率と影響度の格付けを掛け合わせた順位づけを、判定の根拠にしない
- R1 に当たる決定は人確定。「比較した選択肢」の欄が必須で、採否の理由は人が書く(AI は案とリスクの見積を示してよい)
- 差し戻しは基準の項目番号で書く
- 判定した版から判断記録を変える場合は、変更後の版でこのゲートの判定を受け直す。変更の契機(技術検証の結果・顧客の要望・障害など)によって、受け直すゲートを変えない。元の判定記録は残す(標準 第4章「確定した版を変える場合」)

## 事業決裁者が受容を拒否した場合

| 拒否の理由 | 差し戻し先 |
| --- | --- |
| 別の技術的選択で回避しうる | G-3 へ差し戻す(基準4) |
| どの技術的選択でも受容できない | G-2 へ差し戻す |
| 案件の前提が崩れている | 中止の判断へ上程する(第7章 7.7.3) |

「受容できないが進める」を通常の経路として認めません。認めるなら例外承認(`reference/exception-paths.md`)。

## 機械の検査

- 判断記録の欄の形式的な欠落(空欄・単一の値・「なし」)と、前の判断記録との記述の一致を検査する仕組みは、このテンプレートに無い(限界)
- 置き換えの両側の参照と置き場は `scripts/gate/check-decisions.mjs` が検査する
- 出荷判定の証跡の集約は、判断記録を状態ごとの件数と、両側の参照の不一致の件数で出す。判断記録の数を指標にしない
