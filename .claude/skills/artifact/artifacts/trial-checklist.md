# 試行前チェックリスト(T-1 開始条件)

- 様式の正本: `templates/trial-checklist.md`(標準 第8章「社会実装の段階の調整」の写し。標準の様式番号を持たない)
- 置き場: `docs/trial-checklist.md`
- 標準: 第8章「社会実装の段階の調整」、附属書H H.3(サンドボックスは内部監査を免除しない)

## 目的・読み手・形式

- 目的: T-1 の限定試行を、全項目を確認してから始めるための記録。撤退の条件の無い試行と、期限の切れた免除のままの試行を止める
- 読み手: 試行の責任者(開始を決める)、内部監査(附属書H H.3 の観点5 で照合する)
- 形式: 5群(体制・前提条件・測定・差し引き・撤退)のチェックの行と、サンドボックスによる免除の表

## 作成の手順

1. `cp templates/trial-checklist.md docs/trial-checklist.md`。T-1 は体制の人数によらず実施する(1〜2名の体制では、案件そのものが試行になる)
2. 確認した項目に印を付ける。該当しない項目は、印を付けず「該当なし: <理由>」と書く。**項目を消さない**
3. 既存の品質マネジメント規程か決裁権限規程の条項の手続を免除する場合だけ、免除の表に行を書く。期限は YYYY-MM-DD。申請の様式・承認者は採用組織が定める
4. 延長は、元の期限を書き換えず、「延長の決定」に新しい期限と決定の記録の所在を書き足す
5. `node scripts/gate/trial-checklist.mjs` が 0 で終わってから、試行を始める。**印を付けるのも、試行を始めると決めるのも人**。AI の担い手は項目を確認済みにしない

## レビューの観点

- 印の付いた項目が、実際に満たされているか(機械は確かめない)
- 「該当なし」の理由が、体制に照らして成り立つか
- 免除が、本標準の要求事項(附属書H H.3 の内部監査を含む)に及んでいないか。免除できるのは既存規程の条項の手続だけ

## 機械の検査

```bash
node scripts/gate/trial-checklist.mjs        # 形の問題があれば終了コード 1
```

- 様式の項目の欠け、印の無い項目、理由の無い「該当なし」、期限の無い免除、延長の決定の無いまま期限を過ぎた免除を出す
- `/pit` は、置いた写しに問題があれば注記に出す。写しが無い場合は、G-1 の通過の前だけ注記に出す
- 試行を始めた時点は、機械が観測できない
