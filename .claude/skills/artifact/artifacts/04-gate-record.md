# テンプレ4: ゲート判定記録

- 様式の正本: `templates/04-gate-record.md`(欄はここで確かめる。この補助ファイルは欄を列挙しない)
- 置き場: `docs/gates/<ゲート>-<対象>-<日付>.md`
- 書く手順: `/gate <ゲート>` を使う。手順とゲートごとの補助ファイルは `.claude/skills/gate/`
- 標準: 第6章 テンプレ4、第4章「判定の成立」

## 目的・読み手・形式

- 目的: **判定の成立要件**。記録の作成をもって判定が成立する。記録の無い状態は、基準をすべて満たしていても未判定
- 読み手: 品質保証・監査。G-7 で出荷判定者が完備を確かめ、出荷判定の証跡の集約が欄を読む
- 形式: 判定の結果は「通過 / 差し戻し」の2値だけ(条件付き通過は無い)。確定の形態(人確定・協働・委任)、参照した D-0 の版、差し戻しは基準の項目番号で書く。G-6 は挙動要約、G-8・SG・例外承認は決断の記録、R1 と例外承認は比較した選択肢を持つ

## 作成の手順

`/gate <ゲート>` の手順に従う。ここでは要点だけを置く。

1. 判定者が判定する。**AI は判定しない。結果の欄を先に埋めない**
2. 材料と基準の突合の表は AI が起こしてよい。人の判断が要る項目には材料だけを書き、結論を書かない
3. 記録を書いてから `state:*` ラベルを動かす(逆にしない)
4. 成立済みの記録は、体制の変化点の後も書き換えない

## レビューの観点

- 判定者が1人で、席の責任者(人)か。AI の名義が判定者に無いか
- 差し戻しの理由が、当該ゲートの判定基準の項目番号で書かれているか。次工程の材料の未完成を理由にしていないか
- 参照した D-0 の版が、構成の `d0Version` と一致するか
- 決断の記録の「確認していない事項」が空欄・「なし」でないか
- G-8 では、照らした層1 の版・上申(届けた先と日付、または「該当なし」)・品質保証の対象外として出荷することの受容(層1 の項目4 の権限者の記名、または「該当なし」)の3行が書かれているか。異議を退けて受容したのに上申の日付が無くないか
- SG(ステージ移行ゲート)と第三者による棚卸しの記録は「AI の利用の評価」の節を持ち、6欄が埋まっているか(総費用の内訳は企画書から実績で転記)
- 停止の申し立ての解除の記録(ゲート欄「停止の申し立ての解除」)は、様式の「停止の申し立ての解除」の節を持つか。解除した者が層1 の権限者か。見解を退けた解除に上申先と日付があるか

## 機械の検査

- 出荷判定の証跡の集約(`node scripts/gate/aggregate-evidence.mjs`): 当該出荷の範囲で追加された記録の有無、判定者・結果、参照した D-0 の版、G-6 の挙動要約、G-8 の出荷判定者の異議の欄と、照らした層1 の版・上申・対象外の受容の3行、停止の申し立ての解除の記録の成立、ゲート欄に「ステージ移行」「棚卸し」を含む記録の「AI の利用の評価」の節と欄の空欄
- G-5(`check-pr.mjs`): 停止の申し立てのラベルが付いた PR では、基底ブランチの解除の記録を読む
- `next.mjs`: 「ゲート」「対象」「結果」を読み、通過した記録があれば次の段階へ進める
