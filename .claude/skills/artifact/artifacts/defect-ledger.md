# 欠陥の台帳(G-7 基準2)

- 様式の正本: `templates/defect-ledger.md`(標準の様式番号を持たない)
- 置き場: `docs/defect-ledger.md`
- 標準: 第4章 G-7「基準1・2 の記録」「欠陥トリアージ基準」

## 目的・読み手・形式

- 目的: 出荷判定(G-7)の基準2(未解決の欠陥)を、出荷判定者が原記録を一件ずつ数えずに確かめるための取り込み口
- 読み手: 出荷判定者(区分ごとの件数をトリアージ基準と突合する)、事業決裁者(G-8 で受容する)
- 形式: 1行1件。重大度(Sev1〜3)・優先度・状態・コア機能か・回避策の所在。既知の欠陥が無ければ表を空にして「既知の欠陥なし」と書く

## 作成の手順

1. `cp templates/defect-ledger.md docs/defect-ledger.md`
2. 欠陥管理の道具(Issue など)から、出荷の前に書き出す。AI の担い手が書き出してよい
3. 重大度は観測可能な事実で決める(技術側)。優先度は事業側の人が決める。**AI は優先度を決めない**
4. 回避策は文書の所在を書く。文書化されていない回避策は無いものとして扱う

## レビューの観点

- 台帳に載っていない既知の欠陥が無いか(機械は確かめない)
- 重大度の判定が観測可能な事実に基づくか。Sev1 と Sev2 の境界(回避策の有無)が正しいか

## 機械の検査

```bash
node scripts/gate/aggregate-evidence.mjs --from <前回のタグ> --to <今回>   # G-7 基準2 の行に、事業ステージ別の区分ごとの未解決の件数が出る
```

- **台帳が無い出荷は記載の欠落**(集約が失敗する)。重大度・優先度・状態の列が無い台帳も同じ
- 出荷の可否は機械が判定しない。出荷判定者が欠陥トリアージ基準と突合する
