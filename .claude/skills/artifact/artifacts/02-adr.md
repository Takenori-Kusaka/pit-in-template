# テンプレ2: 判断記録(ADR)

- 様式の正本: `templates/02-adr.md`(欄はここで確かめる。この補助ファイルは欄を列挙しない)
- 置き場: `context/decisions/NNNN-*.md`
- 書く手順の詳細: `.claude/skills/adr-write/SKILL.md`(このファイルより、そちらの手順を優先する)
- 標準: 第6章 テンプレ2、第4章 G-3

## 目的・読み手・形式

- 目的: 設計上の選択と、**採らなかった選択肢とその理由**を残す。後任者と AI の担い手が、同じ検討を繰り返さず、前提が崩れたときに戻れるようにする
- 読み手: 技術判断者(G-3 で判定する)、後任者、事業決裁者(事業影響の欄を読んで受容を判断する)
- 形式: 決定・比較した代替案(最低1つ)・可逆性・非機能への影響・事業影響。事業影響は観測できる事象で書き、「顕在化が分かる兆候」を必ず書く(「なし」は不可)

## 作成の手順

1. `/adr-write` を実行する。手順はそのスキルが持つ
2. 比較表には、実際に検討した案を書く。採らなかった理由を空欄にしない
3. 事業影響の「回復に要する時間」は幅で書く。金額は任意。書く場合は算定根拠・参照した過去案件・その額にならない条件の3点を併記する
4. 発生確率と影響度の格付けを掛け合わせた順位づけを書かない
5. `context/` への書き込みは PR を経る。エージェントが直接コミットしない
6. 採用済みの ADR の本文は書き換えない。決定を変えるときは新しい ADR で置き換える

## レビューの観点

- 代替案が最低1つ比較され、不採用の理由があるか(G-3 基準4)
- 戻せない選択か、戻せなくなるものが何かが書かれているか(G-3 基準3)
- 非機能(性能・可用性・セキュリティ)への影響が書かれているか(G-3 基準1)
- 恒久層の設計標準(`context/standards/`)と整合しているか(G-3 基準2)
- 事業影響の5項目に空欄が無いか。兆候が観測できる形か(G-3 基準5)

## 機械の検査

- 欄の空白・回復時間が単一の値・兆候が「なし」の検査は、標準が機械で検査してよいとする対象だが、**このテンプレートには検査の実装が無い**。判定者が確かめる
- 出荷判定の証跡の集約(`aggregate-evidence`)は、`context/decisions/` の判断記録の有無を数える(内容は判定しない)
