# テンプレ5: 運用引き継ぎ文書

- 様式の正本: `templates/05-handover.md`(欄はここで確かめる。この補助ファイルは欄を列挙しない)
- 置き場: `docs/handover.md`
- 標準: 第6章 テンプレ5、第4章 G-7 基準4、運用フェーズ(インシデント対応とポストモーテム)

## 目的・読み手・形式

- 目的: 出荷した後に、運用する人が監視・連絡・復旧を引けるようにする。受け取る側が自分の言葉で再構成できることを確かめるのが望ましい(テンプレート独自。標準の G-7 基準4 が求めるのは、監視項目・障害時の連絡先・復旧手順の完備である)
- 読み手: 運用担当・後任者。障害時に当番が復旧手順と連絡先を引く。G-7 で出荷判定者が完備を確かめる
- 形式: 監視項目(正常範囲と異常時の一次対応)、障害時の連絡先・体制(コア機能の理解保持者)、復旧手順、既知の負債・制約(台帳の ID)
- G-7 が有効な構成では必須

## 作成の手順

1. `cp templates/05-handover.md docs/handover.md`(初回の出荷の前)
2. コア機能ごとに理解保持者を1行に1名で書き、**本人以外の確認した者と、確認の記録と確認日**を書く。確認した者の無い名前・本人が確認した名前・確認日が層1 の力量の確認の周期を過ぎた名前は保持者に数えない。機能ごとに、関わる登録した変更種別を書く(空欄はすべての種別、関わらなければ「なし」)。**理解保持者が1名以下の機能に関わる登録した変更種別は、委任の判定が止める**(L1 へ。標準 第5章 5.4.6)。保持者が1名以下の状態は列挙に無い離脱として扱い、是正の期限と責任者を技術負債台帳へ登録し、層1 の権限者が期限つきで受容する(標準 第3章 3.4.3)
3. 切り戻しは、**実行した実績のある経路だけ**を戻せる経路として書くのが望ましい(テンプレート独自。標準が実績を条件にするのは、委任の条件4 である。第5章 5.5.4)
4. 復旧手順は AI が生成してよい。人が検証した手順だけを載せ、検証した旨を書く
5. 既知の負債は、技術負債台帳の ID で参照する。内容を写さない
6. 障害時の連絡先と指揮系統は、D-0 の障害時の指揮系統(様式の節7)と食い違わせない。障害時の手順: `artifacts/incident.md`。節5 の「障害時の連絡先」(標準の G-7 基準4 が求める項目)は、事象ごとに最初に連絡する先・連絡の手段・応答が無いときの次の連絡先を表に書き、表の下の「エスカレーション順序」の行へ順序を書く(表はテンプレート独自。標準 第6章 テンプレ5 は保持者の表とエスカレーション順序の行を持つ)
7. 出荷のたびに、変わった監視項目・手順を更新する(テンプレート独自。標準は更新の頻度を定めていない)

## レビューの観点

- 監視項目に、正常範囲と異常時の一次対応があるか
- 連絡先が役割と人の両方で引けるか。理解保持者が1名だけのコア機能が無いか
- 切り戻しの経路に実行の実績があるか
- 受け取る側が、文書を読まずに自分の言葉で説明できるか(受け取る側に説明してもらう。テンプレート独自の観点)

## 機械の検査

- 様式を更新する既存の採用者へ: この版から、出荷の証跡の集約が節の置き場を見出しの語で読む。「障害時の連絡先」(または「障害時連絡先」「緊急連絡先」「障害発生時の連絡先」「障害時の連絡体制」)を含む見出しが無い文書は、置き場なしの欠落になり、G-7 を止める。節5 に「### 障害時の連絡先」を足し、表とエスカレーション順序を書いて直す。空欄・様式の初期の文のままも欠落になる

- 出荷判定の証跡の集約(`node scripts/gate/aggregate-evidence.mjs`)は、`docs/handover.md` の有無と、3項目(監視項目・障害時の連絡先・復旧手順)の置き場が在るか、空欄または様式の初期の文のままでないかを見る(`scripts/gate/handover-items.mjs`)。**記入が在ることは完備を意味しない**。閾値の妥当性・連絡先へ届くか・復旧手順の実行の実績は機械で確かめていない。様式の文を書き換えた記載と「TBD」は通る。置き場は見出しの語(「監視」、「障害時の連絡先」ほか連絡先の5語、「復旧手順」または先頭のセルが「切り戻し」の表の行)で読むため、見出しを改めると欠落になる。G-7 の判定者が中身を読んで完備を判定する
- `next.mjs` は、実装済みの機能があり `docs/handover.md` が無いとき、出荷の段階で `/artifact 05` を出す
- 委任の判定(`check-delegation.mjs`)は、節2 の保持者を判定のたびに数え、1名以下の機能に関わる登録した変更種別を止める。保持者が2名以上へ回復しても、この文書の履歴から導いた回復の日より後の登録の判定(`/process-change`)まで止め続ける。`docs/handover.md` が無い・節2 にコア機能が無い・履歴を読めない場合も、判定できないものとして登録した変更種別を止める。この文書に触れる変更は委任に該当しない

## コンテキスト移管(H-1〜H-3)の記録の書き方

結果責任者(A)・文脈オーナーの交代、理解保持者が1名以下になる交代では、標準 第2章 2.9 のゲート H-1・H-2・H-3 の記録を要する(適用は `/process-change` の種別 accountable が残作業として渡す)。専用の様式は無く、記録の置き場は採用者が決める。この節は、書く内容の例である。

- 移管は、口頭説明の完了では成立しない。後任者が前任者へ問い合わせずに判断できる状態をもって成立とし、判定は H-3 で行う
- この文書の「運用上の勘所」に当たる記載(監視値の読み方・壊れやすい箇所)は、H-2 の書き戻し先の1つである

### H-1 移管準備の記録(価値責任者が判定)

次の欄を、人が書く。予告期間の区分は申告せず、通知日と交代日から導く。

| 欄 | 書くこと | 点検(人が読む。機械の検査は足さない) |
| --- | --- | --- |
| 交代の通知日 | 交代が本人へ通知された日(組織の内部で決めた日ではない) | 空でない |
| 交代日 | 交代の日 | 空でない。通知日以降 |
| 予告期間(営業日) | 通知日から交代日までの営業日数 | 通知日と交代日から導いた値と一致する |
| 前任者の関与の延長 | 期間(交代後の日付)/ 稼働の目安(週あたりの時間)/ 連絡手段と応答の期限 / 繰り越した項目 | 予告期間が10営業日未満なら、4項目がすべて埋まっている。「必要に応じて協力する」は延長として認めない |

欠落の棚卸しは、コンテキスト基盤に記録されていない知識を、次の4類型で洗い出し、書き戻し先を特定する。コア機能ごとの理解保持者数もあわせて数える(数え方は上の節2)。

| 類型 | 書き戻し先 |
| --- | --- |
| 設計の背景と制約 | 判断記録(ADR) |
| 却下した選択肢 | 判断記録(ADR)の代替案欄 |
| 運用上の勘所 | この文書 |
| 組織的文脈 | D-0 と恒久層コンテキスト |

### H-2 書き戻しの記録(文脈オーナーが判定)

- 前任者が書き、後任者がレビューする。順序を逆にしない
- AI が草案を生成してよい。却下した選択肢と当時の制約は、人が記入する
- 完了は、追記の分量ではなく、H-1 で特定した欠落項目の消化で判定する
- 期限と範囲は予告期間で決める。期限は交代日を基準とする相対の指定である

| 予告期間 | H-2 の期限 | 書き戻す範囲 |
| --- | --- | --- |
| 20営業日以上 | 交代日の10営業日前まで | H-1 で特定した欠落の全部 |
| 10〜19営業日 | 交代日の5営業日前まで | 全部 |
| 5〜9営業日 | 交代日の前営業日まで | 優先順位の上位2類型(残りは交代後へ繰り越す) |
| 5営業日未満 | 交代日の前に H-2 を置かない | 全部を交代後へ繰り越す |

- 繰り越しがあるときは、前任者の関与の延長を H-1 の判定と同時に確定させる。確定していない案件を H-1 で通過させない
- 短い予告のときの優先順位は、1 組織的文脈、2 運用上の勘所、3 設計の背景と制約、4 却下した選択肢。入れ替えない

### H-3 理解の実証の記録(前任者でも後任者でもない者が判定)

評価者・評価方法・課題・結果を記録する。評価者に前任者と後任者のいずれも充てない。自己申告では判定しない。

| # | 課題 | AI への問い合わせ |
| --- | --- | --- |
| 1 | 設計の説明(記録を参照せずに設計判断と理由を説明する) | しない状態で実施 |
| 2 | 却下案の再構成(採らなかった選択肢を1つ以上挙げ、理由を説明する) | しない状態で実施 |
| 3 | 障害時の初動(過去の障害事例について一次切り分けを挙げる) | しない状態で実施 |
| 4 | 変更の実作業(小規模な変更を独立レビューの通過まで単独で完遂する) | 利用を制限しない |

後任者が準備段階で AI を使うときは、生成された説明をそのまま受け取らない。疑問点を問いとして立て、回答の根拠を記録と突き合わせる。使い方を観測する機械の手段は無い。H-3 の不合格を、後任者の人事評価に用いない。
