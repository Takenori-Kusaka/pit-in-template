# テンプレ5: 運用引き継ぎ文書

- 様式の正本: `templates/05-handover.md`(欄はここで確かめる。この補助ファイルは欄を列挙しない)
- 置き場: `docs/handover.md`
- 標準: 第6章 テンプレ5、第4章 G-7 基準4、運用フェーズ(インシデント対応とポストモーテム)

## 目的・読み手・形式

- 目的: 出荷した後に、運用する人が監視・連絡・復旧を引けるようにする。**引き継ぎは文書の受け渡しでは完了しない**。受け取る側が自分の言葉で再構成できて、はじめて成立する
- 読み手: 運用担当・後任者。障害時に当番が復旧手順と連絡先を引く。G-7 で出荷判定者が完備を確かめる
- 形式: 監視項目(正常範囲と異常時の一次対応)、障害時の連絡先・体制(コア機能の理解保持者)、復旧手順、既知の負債・制約(台帳の ID)
- G-7 が有効な構成では必須

## 作成の手順

1. `cp templates/05-handover.md docs/handover.md`(初回の出荷の前)
2. コア機能ごとに理解保持者を1行に1名で書き、**本人以外の確認した者と、確認の記録と確認日**を書く。確認した者の無い名前・本人が確認した名前・確認日が層1 の力量の確認の周期を過ぎた名前は保持者に数えない。**理解保持者が1名になった機能は、AI 自律レベルを引き下げる**
3. 切り戻しは、**実行した実績のある経路だけ**を戻せる経路として書く。一度も戻したことのない経路を数えない
4. 復旧手順は AI が生成してよい。人が検証した手順だけを載せ、検証した旨を書く
5. 既知の負債は、技術負債台帳の ID で参照する。内容を写さない
6. 障害時の連絡先と指揮系統は、D-0 の障害時の指揮系統(様式の節7)と食い違わせない。障害時の手順: `artifacts/incident.md`
7. 出荷のたびに、変わった監視項目・手順を更新する

## レビューの観点

- 監視項目に、正常範囲と異常時の一次対応があるか
- 連絡先が役割と人の両方で引けるか。理解保持者が1名だけのコア機能が無いか
- 切り戻しの経路に実行の実績があるか
- 受け取る側が、文書を読まずに自分の言葉で説明できるか(受け取る側に説明してもらう)

## 機械の検査

- 出荷判定の証跡の集約(`node scripts/gate/aggregate-evidence.mjs`)は、`docs/handover.md` の**有無だけ**を見る。監視項目・連絡先・復旧手順の完備は機械で確かめていない。G-7 の判定者が中身を確かめる
- `next.mjs` は、実装済みの機能があり `docs/handover.md` が無いとき、出荷の段階で `/artifact 05` を出す
