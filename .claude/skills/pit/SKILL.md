# 次の一手を出す

プロセスの全体を覚えておく必要はありません。次の一手は、状態から機械が出します。

## 手順

### 1. 状態を出す

```bash
node scripts/gate/next.mjs
```

自分のロールが分かっている場合は、ロールを指定します。ロールの判定するゲート・判定してはならないゲート・受信箱のコマンド・引き渡しのラベルも出ます。

```bash
node scripts/gate/next.mjs --role <ロール>
```

### 2. 出力に従う

| 出力 | すること |
| --- | --- |
| `[次のコマンド]` | そのコマンド(スキル)を実行する。「読む:」の行があれば、そのファイルを読んでから実行する |
| `[人の判断待ち]` | **終端です**。コマンドを実行しない。待つ席の受信箱のラベルを付けて渡し、利用者へ「誰の何の判断を待っているか」を伝える |
| `[判定できない]` | 推測で進めない。理由を利用者へ伝え、人に状態を確かめてもらう |
| `[完了]` | その機能について、することはない |

機能が複数ある場合は、機能ごとに一手が出ます。1つにまとめないでください。

「注記(段階を止めない)」には、体制の変化点の後に生じた状態が、担当の席と次の一手つきで出ます。検出率の測定値の失効(AI の層・人の層)、後継不在の席、依存先の欄の空欄・代替なし・退出未実施、席の責任者本人の力量の確認の未確認・失効と、確認した者が名簿の外の記録、実環境の統制(ブランチ保護・PR のレビューの取得・ship-evidence の成果物)の未確認、10名以上の規則です。10名以上の規則には、直近の出荷の集約の出力(`evidence/evidence.json`)が手元にあれば、項目1 の件数(「同じ所属の承認者だけ N 件(#…)」、出荷判定者の所属)を集約と同じ文で添えます(集約の後に既定ブランチが進んでいれば、その旨も出ます)。**注記を消すのは人の作業**(tally のやり直し、D-0 節15 の受容、`/process-change` での記入、実環境での `env-check`)であり、AI の担い手は解消したことにしません。出荷の証跡の集約(項目4・6・7)と同じ読み取りです。構成に `coreReviewerCount`(第8章 軸C「高」)がある体制では、G-6 の注記に「**コア機能の独立レビューは N 名**(パス: …)」が常駐します(パスが未宣言なら「確かめられない」と出る。コア機能のパスは、確約範囲・コア指定のパス `delegation.protectedPaths` と区分の下限の規則 `riskFloor.rules` のパス)。層1 項目4「AI の利用の拡大」の水準が `認めない` で始まる組織では、委任の登録が構成で拒否されることと、構成に委任の登録が残っていればその旨が注記に出ます。委任の規則の承認が決定者と同一人物だった変化点も注記に出ます。

### 3. 利用者へ示す

出力のうち、利用者に関係する行をそのまま示します。言い換えて要約しないでください。

## このスキルがしないこと

- 状態を推測で補うこと。出力に無い一手を足すこと
- 人の判断待ちを飛ばして、次の段階のコマンドを実行すること
- PR・ラベル・CI の状態の判定(`next.mjs` はローカルの git だけを見ます。見ていないものは出力の末尾に出ます)
