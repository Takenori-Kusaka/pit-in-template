# 種別 notice: 即時通知の記録、承認権限の一時制限

変化点に数えません。`/process-change` の手順7 もこのファイルの内容です。

## 即時通知の対象

次の変化点は、**出荷判定者の席の責任者へ即時に知らせる対象**です(標準 第3章 3.13.6)。出力に `[即時通知]` が出ます。

| 対象 | 検出 | 通知する者 |
| --- | --- | --- |
| 人数の境界の通過 | チーム規模の回答が変わった | 文脈オーナー |
| 運用形態の変更 | いずれかの席の運用形態が変わった(引き下げを含む) | 対象の席の責任者 |
| 検出の層に数えている AI の担い手の識別の変更 | いずれかの席の担い手の識別が変わった(検出率の測定値が失効する) | AI維持管理者と AI運用担当者 |
| 承認権限の一時制限(標準 第7章 7.9)の発動 | 構成に現れないため、種別 `notice` で記録する | 発動を記録した者 |
| G-6 が成立から未達・成立しないへ変わる変化 | G-6 が適用・未達なしから、未達または適用しないへ変わった(2名のままの変化を含む) | 文脈オーナー |
| 出荷判定者の席の責任者の交代 | 替わった、または空いた | 文脈オーナー |

## 通知先

- 通知先は出荷判定者の席の責任者。**交代では前任者にも知らせる**。前任者が体制から外れていれば、D-0 表1「体制と運用形態」の決定者へ
- **出荷判定者の席が空いた場合は、前任者(名簿に残っていれば)、D-0 表1 の決定者、品質保証部門の通知先(`governance.qaNotice`)の順に通知先を決める**。いずれも無ければ「通知する者と通知先が同一」として自動で記録する(`notice.noTarget`)。席が空いた場合の順と、宛先が無い場合の扱いは、テンプレート独自である(標準 第3章 3.13.6 が定めるのは、新任と前任、前任が外れた場合の決定者まで)
- 通知先の記名は、名簿の人へ正規化して記録する。品質保証部門の通知先を `notice.to` へ書けるのは、人の通知先が無い場合と、通知する者と人の通知先が同一の場合。名簿の人でない名義は、そのまま記録し、表示で区別する
- `governance.qaNotice` を定めていれば、すべての即時通知をそこへも送る。前任者・決定者・部門の通知先は、構成から `notice.also` へ自動で記録され、`notice.at` の日にあわせて送ったものとして扱われる
- **通知する者と通知先がすべて同一人物の場合(1人体制など)は、通知の入力を求めない**。「通知する者と通知先が同一」と自動で記録する(`notice.self`)。部門の通知先を定めている場合は、部門へ送った日を記録する

## 記録のしかた

**エージェントが通知を済ませたことにしません**。通知先と通知日は、利用者から受け取ります。通知が済んでいれば、変化点の入力へ書きます。

```json
"notice": { "to": "<出荷判定者の席の責任者の氏名>", "at": "2026-10-01" }
```

適用の後で通知した場合は、過去の記録を書き換えず、種別 `notice` の記録を追記します。`noticeFor` は、対象の記録の `changeLog[]` の添字です(契約検査の注意と、適用時の残作業に出ます)。

```json
{ "kind": "notice", "summary": "出荷判定者の席の責任者へ知らせた", "noticeFor": 3, "notice": { "to": "<氏名>", "at": "2026-10-02" } }
```

承認権限の一時制限の発動は、次の形で記録します。範囲(`paths`)・対象の人(`person`)・根拠となった測定結果の所在(`basis`)・記録した者(`recordedBy`。品質保証の機能を担う人)を必ず書きます(標準 第7章 7.9.6)。範囲を限定しない制限は書けません(7.9.2「適用の範囲」)。

```json
{ "kind": "notice", "summary": "注入した欠陥を連続2回見逃した", "event": "restriction",
  "restriction": { "id": "pay-1", "person": "<検出能力の低下を検知された者>", "paths": ["src/payments/**"], "basis": "<注入の記録の所在>", "recordedBy": "<記録した者>" },
  "notice": { "to": "<氏名>", "at": "2026-10-02" } }
```

解除は、発動の識別子を引いて記録します。**期間の経過では解除しません**(7.9.3)。解除の根拠は、注入した欠陥を連続2回検出したことです。

```json
{ "kind": "notice", "summary": "注入した欠陥を連続2回検出した", "event": "restriction-release",
  "restriction": { "id": "pay-1", "basis": "<検出の記録の所在>", "recordedBy": "<記録した者>" },
  "notice": { "to": "<氏名>", "at": "2026-10-20" } }
```

- 出荷の証跡の集約は、解除されていない制限の範囲に触れる変更で、独立した人の確認に数えた承認が2名に満たないものを、独立した人の確認に数えません(だれが承認したかに依らない)。強制する承認の数(ブランチ保護)は変えません。発動と解除は人が記録し、機械は発動しません
- 範囲を書かずに記録した旧い発動の記録は、範囲を判定できないとして保証の開示の項目1 に出ます。範囲を書いた発動を記録し直すか、解除を記録します
- **エージェントが制限を発動・解除しません**。範囲・対象の人・根拠は、記録した者から受け取ります

**通知先と通知日が未記入の即時通知は、出荷判定の証跡の集約が、記録の欠落として扱います**。
