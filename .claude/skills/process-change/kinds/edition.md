# 種別 edition: 従う本標準の版の切り替え

構成が従う本標準の版(`process.config.json` の `standard.edition`)を、発行された版へ切り替えます(標準 第1章 1.10.3)。**変化点に数えません。適用の開始を動かしません**(同 1.10.1)。

```json
{ "kind": "edition", "edition": "第2版", "summary": "第2版へ切り替え、宣言をやり直した", "decidedBy": "<記名の自然人>", "reason": "<切り替える理由>" }
```

- `edition` は、発行された版を「第N版」または「第N版 修正M」で書く。**作業中の版へは切り替えない**。作業中の版は、適用の表明に限りコミットとともに名指せるが、2つの適合の主張には名指せない
- 切り替えられるのは、複製した知識ベース(`scripts/vendor/tailoring-kb.json` の `source.edition`)の版だけである。発行の時点に生成した知識ベースだけが版を持つ(発行の後の知識ベースは `source.edition` が `null`、`source.basedOn` が最後に発行した版)。先にその版の知識ベースを複製する。知識ベースの版と異なる版を書くと、スクリプトが拒否する
- 決定した者(`decidedBy`)と理由(`reason`)を要する。**AI の名義を書かない**。名前と理由を推測で埋めない
- 切り替えると、新しい版の規則で構成を導き直す。差分は `--dry-run` で示す。緩める向きの差分があれば、緩める向きの変更として扱う(`reference/direction.md`)
- 新しい版への適合の主張は、この記録の日付の後の範囲に限る。前の版への主張は、期限なく続けてよい。追従していない版への適合は主張しない(標準 第1章 1.10.3)
- 欄の無い旧い構成は、作業中の版に従うものとして読む。版の欄を足すのは、この種別だけである
