# 種別 axis: 軸B〜E の入力の変化

標準の番号: 5。ステージ移行(軸B)、規制への該当、委託への切替、安全重要度などの回答の変化。主に変わるもの: `answers`。キーの一覧: `../reference/input.md`

```json
{
  "kind": "axis",
  "summary": "SG-0 を通過し、価値確立(S1)へ移る",
  "answers": { "q-biz-phase": "mvp" },
  "decidedBy": "<D-0 表1「体制と運用形態」の決定者>",
  "reason": "<SG-0 の判定の結果>"
}
```

- 回答の文言は `scripts/vendor/tailoring-kb.json` の `questions` のものをそのまま使う。知識ベースに無い質問と選択肢は拒否される
- 決定できるのは、D-0 表1「体制と運用形態」の決定者に限る(席を特定できない決定)
- 差分の「構成の差分」に、有効になる・外れるゲート、ブランチ保護の付け替え、カバレッジの下限の導出値の変化が出る。そのまま利用者へ示す

## ステージの変更

- ステージを先へ進める変更は、SG の判定の結果を反映する(`.claude/skills/gate/gates/SG.md`)。ゲートを省略へ変える部分を含む場合は、緩める向きとして扱う
- **ステージを前へ戻す変更は、SG の判定記録を要する**。`sgRecord` に `docs/gates/` 配下の実在する判定記録(.md)を書く。決定者の記名も要する

```json
{ "kind": "axis", "summary": "S1 から S0 へ戻す", "answers": { "q-biz-phase": "poc" }, "sgRecord": "docs/gates/sg1-P-001-2026-10-01.md", "decidedBy": "<決定者>", "reason": "<理由>" }
```

- 探索ステージ(S0)の期間中、実装スタックは未確定でよい。SG-0 の通過後に未確定が残ると未達。スタックの確定は種別 `settings`(`settings.md`)

## 安全重要度・規制への該当

- 安全重要度が上がり委任を適用できなくなったときは、**抜き取り待ちの委任の変更を、協働の手続で全件確認し直す**(残作業に出る)
- 安全重要度 CL1 以上・規制業で体制が3名を割る場合は、拒否されずに `shipBlocked` が立つ。選択肢(体制の確保・設計で区分を下げる・機能を実施しない)を選ぶのは人(`../reference/dry-run.md`)
- 区分を下げる根拠にできるのは、危害の帰結を設計で下げたこと(テンプレ9 の RRS1。記録を要する)。安全重要度を下げる変更は緩める向き
- 委託への切替では、AI-SLA 合意確認書(`/artifact 08`)と、委任の適用の合意を確かめる

## 即時通知

軸の変化で G-6 が成立から未達・成立しないへ変わる場合は、即時通知の対象です(`notice.md`)。
