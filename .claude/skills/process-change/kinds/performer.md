# 種別 performer: AI の担い手の識別の変更

標準の番号: 4。モデルの版・提供者、指示資産の恒久層、ツールと権限、実行基盤のいずれかが変わったとき。主に変わるもの: `seats[].performer`、`seats[].qualification`。キーの一覧: `../reference/input.md`

```json
{
  "kind": "performer",
  "summary": "開発者の席の担い手のモデルの版を上げる",
  "seats": {
    "dev-verifier": {
      "performer": { "model": "<モデルの版>", "instructions": "<指示資産の版>@<識別子>", "permissions": "<権限の組>" },
      "qualification": { "confirmedAt": "2026-10-01", "performedBy": "<AI維持管理者の席の責任者>", "approvedBy": "<当該の席の責任者>", "cases": "<用いた事例>", "result": "<結果>", "performer": { "model": "<新しい識別>", "instructions": "<同>", "permissions": "<同>" } }
    }
  },
  "decidedBy": "<当該の席の責任者>",
  "reason": "<新しい識別で委任を続ける理由>"
}
```

- 指示資産の版は、末尾へ `@<識別子>` を書くと、契約検査が実ファイルと照合する。識別子は `node scripts/gate/verify-gate-contract.mjs --instructions-digest` で得る。識別子を伴わない申告は自己申告として表示される
- `.claude/` の指示資産(スキル・補助ファイルを含む)を変えると識別子も変わる
- 担い手の識別の変更は即時通知の対象(検出率の測定値が失効する。通知する者は AI維持管理者と AI運用担当者。`notice.md`)
- 適合性確認の記録・識別・権限の組は、利用者から受け取る。推測で書かない

## 適合性確認は失効する

**AI の担い手の識別を変えると、適合性確認の記録は失効します**。新しい版を採用する前に確認を済ませておき、識別の変更と同じ変化点で記録を出すことはできます。その記録で委任を続けられるのは、次の4つをすべて満たす場合だけです。1つでも欠ければ、席は協働へ下がります(出力に `[即時反映]` と、欠けたものが出ます)。

1. 記録の担い手の欄(`performer`)が、新しい識別と一致する
2. 旧い記録の使い回しでない(`confirmedAt` が、旧い記録の確認日より後)。旧い記録の欄を書き換えて出したものは受け付けられず、`[無効]` と出る
3. 実施者が AI維持管理者の席の責任者、承認者が当該の席の責任者である
4. 当該の席の責任者が、新しい識別で委任を続ける決定として記名し、理由を書く(`decidedBy`・`reason`)

条件4 の記名は、**当該の席の責任者に限ります**。D-0 表1「体制と運用形態」の決定者の記名では、協働へ下がります。

- 保持していた委任の宣言は、担い手の識別が変わると取り下げられる(`[宣言の失効]`。`mode.md`)
- 適合性確認を経ていない担い手を委任で運用しない。再確認と席の責任者の記名があるまで、協働が上限
- 認証情報: 交代した担い手のトークンを失効させ、新しい担い手へ別のトークンを発行する(人が行う。残作業に出る)
- 一時的な切り替え(障害の間だけ別の担い手を使う)は、この種別でなく `outage.md` の `switched`
