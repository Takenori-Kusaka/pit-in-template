# 種別 accountable: 責任者の増減・交代・長期の不在、兼務の変更、名簿

標準の番号: 1。主に変わるもの: `people[]`、`seats[].accountable`。キーの一覧: `../reference/input.md`

## 任免の決定

- **席の責任者の任免(任命・交代・空いた席への後任の配置)は、統制の向きにかかわらず決定**。D-0 表1「体制と運用形態」の決定者の記名(`decidedBy`)と理由(`reason`)を要する
- 決定者その人を替える変更(決定者の席の責任者の交代、`governance` の変更)は、**前任の決定者の記名**を要する。前任者が体制から外れている場合は、組織上の任命権者(名簿へ `external: true` と `appointer: true` で、この変化点より前に記載した人)の記名を要する
- **新任の決定者が、自分の任命を自分の記名で確定することはできない**(標準 第3章 3.13.3)
- 人が体制から外れて席が空くことは発生であり、記名を要求しない。**離脱と後任の任命を同じ入力で出さない**。離脱(席を `null`)だけを先に反映し、後任は別の変化点で出す
- 初期化の直後の初回の記入は、名簿と全席を1回の変化点で出し、決定者の席に記入する人の記名と理由で受け付ける(人数に依らない)
- **技術判断者と AI運用担当者を同じ人にしない**(3名以上の体制)。兼務禁止ではないため拒否されないが、評価用の基準集合の範囲の承認(AI運用担当者が起案し、技術判断者が記名で承認する。標準 第3章 3.12.3 の要求事項10)を別の自然人で行えず、出荷の証跡の集約は承認に数えない。出力の注記に出る。AI運用担当者は品質管理側(出荷判定者と同じ側)の人に置く

```json
{
  "kind": "accountable",
  "summary": "名簿と席の責任者を記入する(初回の記入)",
  "people": [{ "id": "p1", "name": "<氏名>", "accounts": ["<アカウント>"] }],
  "seats": { "value-owner": { "accountable": "<氏名>" }, "biz-approver": { "accountable": "<氏名>" } },
  "decidedBy": "<決定者の席に記入する人の氏名>",
  "reason": "<理由>"
}
```

## 席の責任者本人の力量の確認(第3章 3.4.3 要求事項1)

- 判断を担う席(価値責任者・技術判断者・独立レビュア・出荷判定者)の責任者は、**任命時**と層1 の「AI を使わない力量の確認の周期」で、AI を使わずに判断できる力量の確認を受ける。確認の記録は `seats.<席>.competence` に書く(`{ "confirmedAt": "YYYY-MM-DD", "confirmedBy": "<本人以外の確認した者>", "record": "<確認の記録の所在>" }`)。任命と同じ変化点で書いても、確認の後に別の変化点で書いてもよい。**記録だけの変化点に決定者の記名は要らない**
- 確認した者は本人以外の自然人(自己申告は認めない。3.4.3 要求事項2)。AI の名義、未来の確認日は拒否される。記録の所在は、AI を使っていないことをログで確かめられる期間の成果物、または判定者の面前の演習の記録(類型E を兼ねてよい)
- 責任者が交代すると、前任の記録は引き継がれない。新任の責任者の記録が無いあいだ、出荷の証跡の集約の項目7 と `/pit` に「未確認(確認を経ない任命)」と出続ける。確認日が周期を過ぎると「失効」と出る。出荷は止めない
- D-0 節9 の「席の責任者本人の力量の確認」の表は、この記録から生成する(手で書かない。手で書くと `check-d0` が失敗する)。**確認の記録を利用者から受け取っていないのに書かない**
- `confirmedBy` は人の名簿の外の人でもよい(外部の研修機関、前任の部門長、品質保証部門の長など)。名簿の外なら拒否せず受け付け、構成の差分・残作業・D-0 節9・出荷の証跡の集約の項目7・`/pit` に「(名簿の外)」と出る。名簿の外の名前は機械で突合できないため、確認の記録(`record`)に所属・役職を書く。内部監査の観点6(名簿の実在)で突合する

```json
{ "kind": "accountable", "summary": "独立レビュアの新任の責任者の任命時の力量の確認を記録する", "seats": { "independent-reviewer": { "competence": { "confirmedAt": "2026-10-07", "confirmedBy": "<技術判断者など本人以外>", "record": "docs/drills/competence-<氏名>-2026-10-07.md" } } } }
```

## 名簿(people)

- **書くと名簿の全体を置き換える**。`{ "id", "name", "external", "appointer", "accounts", "nameConfirmed", "team" }`
- `team` は所属(チーム・部門。任意)。10名以上の規則(コア機能の独立レビューに別チームを含める、出荷判定は QA 部門・専任)を出荷の証跡の集約が項目1 で確かめるときに使う。無ければ「判定できない」「確かめられない」と出る。記入があるときだけ D-0 節1 の名簿の表に「所属」の列が出る
- `external: true` は外部の確認者(体制の人数に数えない)。`appointer: true`(`external: true` と併用)は組織上の任命権者で、確認者ではなく、席の責任者にもしない。決定者が体制に残っている間に任命権者を名簿へ置くのは、決定者の記名を要する
- 席の責任者でない担い手(人)も記入する
- `accounts` はリポジトリ上のアカウントの配列。承認したアカウントを名簿の人へ対応づけるために使う。未記入の人の承認は、出荷判定の証跡で「独立した人の確認」に数えない。bot のアカウントと、1つのアカウントを2人へ書く記入は拒否される
- 人を名簿から外しても、その人が在籍中に行った PR の承認と判定記録は、出荷の証跡の集約が承認・判定の時点の名簿(git の履歴の構成)へ対応づけて数える。外した後の承認は数えない。離脱者を名簿に残す必要はない(`headcount.md`)
- 人の名簿へ名前を足すのは人。**利用者から受け取っていない名前を足さない**

### 既存の行を別の人へ書き換えない

- 同じ行(`id`)の氏名とアカウントを両方とも変える入力は拒否される。足したときの値と比べて両方が異なることになる変更も、変化点を分けても拒否される。別の人は新しい `id` の行として足し、席への任命は任免の手続で出す
- 氏名だけ、またはアカウントだけの変更は、同じ人の表記の変更として扱い、D-0 表1「体制と運用形態」の決定者の記名と理由を要する。決定者本人の行の変更は、組織上の任命権者か、本人以外の席の責任者1名の記名を要する
- 旧い値と新しい値は、変化点の記録(`rosterEdits`)・D-0 の改訂履歴・品質レポートの項目7 に残る。出荷判定者の席の責任者の行の変更は、責任者の交代と同じく即時通知の対象(`notice.md`)
- ある人の氏名・アカウント・`id` が、別の人のものと重なる名簿は拒否される

## AI の名義を書かない

- 責任者・決定した者・適合性確認の実施者と承認者・通知先の欄へ、AI の名義を書かない
- スクリプトは、名簿に無い名義、担い手の識別と同じ文字列、AI を示す語(モデル名、agent、bot、AI の表記。全角と片仮名の読みを含む)を含む名義を拒否する。同じ語を含む実在の氏名を通せるのは、人が確認した旨(`nameConfirmed`)を名簿へ書いた場合だけ。**エージェントの判断で `nameConfirmed` を付けない**(利用者が明示した場合だけ)
- 限界: 語の一致による検査であり、役職名や別の文字種で書いた名義は検出できない。名簿のアカウントの記載が正しいかも機械では確かめない(内部監査)

## 交代と適合性確認・委任

- **適合性確認を承認した席の責任者が交代した(離脱を含む)とき、承認は新しい責任者へ引き継がれない**。席は協働へ下がる。失効するのは承認であり、担い手の識別が変わっていなければ確認の記録(事例と結果)は有効なまま。確認を実施した者が外れても記録は有効
- 承認だけをし直して委任へは戻さない場合: `{ "seats": { "dev-verifier": { "qualification": { "approvedBy": "<新しい責任者>" } } } }`(記名は要らない)
- 席の規則も、前任の責任者の記名のままでは働かない。**新しい責任者が委任を引き継ぐときは `takeover` で1つの入力にまとめる**。適合性確認の承認し直し、規則の記名のし直し(前任の記名は `priorDecision` に残る)、委任への復帰を、新しい責任者の記名と理由で受け付ける。同じ席の `accountable` と同時には書けない(任命を先に反映する)。AI維持管理者も交代していれば、新しい AI維持管理者の `ruleApprovedBy` を同じ入力へ書ける

```json
{ "kind": "mode", "summary": "新しい責任者が開発者の席の委任を引き継ぐ", "takeover": "dev-verifier", "decidedBy": "<新しい責任者の氏名>", "reason": "<確認の記録と規則を読んで確かめたこと>" }
```

- AI維持管理者の席の責任者が交代したときは、前任者が承認した規則が承認待ちへ戻る(`mode.md`)
- 出荷判定者の席の責任者の交代は即時通知の対象。前任者にも知らせる(`notice.md`)
- 責任者が未記入の席が、適用するゲートの判定者であれば、そのゲートは止まる。後任・外部の確認者・残った人の兼務のいずれかを利用者に決めてもらう
