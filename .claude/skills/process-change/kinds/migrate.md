# 種別 migrate: 構成の形式の移行・取り込んだテンプレートの記録

構成(`process.config.json`)の形式の版(`formatVersion`)を、この準拠テンプレートの現行の版へ移します。あわせて、取り込んだ準拠テンプレートのコミットと、強制層のファイルの要約値を構成へ記録します(標準 第1章 1.10.3、準拠テンプレートリポジトリの頁「テンプレートの更新の取り込み」)。**変化点に数えません。値を変えません。適用の開始を動かしません**。 <!-- 根拠: IMPL-0316 -->

```json
{ "kind": "migrate", "summary": "構成の形式の版を移し、取り込んだテンプレートを記録した", "templateCommit": "<取り込んだ準拠テンプレートのコミット。分からなければ書かない>" }
```

- 版ごとに、現行の版への直接の変換を当てる。ゲートの状態・席・閾値・名簿の値は変えない。変える必要がある構成(新しい版の検査で落ちる構成など)は、記名を伴う種別(`accountable`・`settings` など)で直す。移行の入力に `settings` や体制の値を書くと、スクリプトが拒否する
- 移行は PR で出す。構成と一緒に、取り込んだテンプレートのファイル(強制層)を変える場合は、強制層の変更として AI維持管理者へ引き渡す(`state:needs-platform`)
- `templateCommit` は、取り込んだ準拠テンプレートのコミットの識別(7〜40 桁の16進)。**推測で書かない**。省くと前の記録を引き継ぎ、記録が無ければ「不明」となる
- 構成の `template` は道具だけが書く。要約値は強制層のファイル(フック・ワークフロー・ルールセット・ゲートと初期化のスクリプト・アダプタ)ごとに取る。契約検査は、記録と現在のファイルの不一致を注記に出す(合否に使わない)。記録は来歴の主張であって証明ではない
- 猶予の期間は置かない。この準拠テンプレートが知らない版(既知より大きい `formatVersion`・`schemaVersion`)の構成は、契約検査が失敗にする。読み込みで既定値を補うのは、結果が同じか厳しくなる場合に限る。緩める向きの補いは無い
- D-0 の改訂履歴に行を足さない。版の欄の無いテーラリングの宣言と D-0 を、遡って書き換えない
