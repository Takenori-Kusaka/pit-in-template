# 種別 migrate: 構成の形式の移行

構成(`process.config.json`)の形式の版(`formatVersion`)を、この準拠テンプレートの現行の版へ移します(標準 第1章 1.10.3、準拠テンプレートリポジトリの頁「テンプレートの更新の取り込み」)。**変化点に数えません。値を変えません。適用の開始を動かしません。取り込んだテンプレートの記録(強制層の要約値)を書き換えません**。 <!-- 根拠: IMPL-0316 -->

```json
{ "kind": "migrate", "summary": "構成の形式の版を移した" }
```

- 版ごとに、現行の版への直接の変換を当てる。ゲートの状態・席・閾値・名簿の値は変えない。変える必要がある構成(新しい版の検査で落ちる構成など)は、記名を伴う種別(`accountable`・`settings` など)で直す。移行の入力に `settings` や体制の値を書くと、スクリプトが拒否する
- 移行は PR で出す。構成と一緒に、取り込んだテンプレートのファイル(強制層)を変える場合は、強制層の変更として AI維持管理者へ引き渡す(`state:needs-platform`)
- 取り込んだテンプレートのコミットと強制層の要約値の記録は、種別 `intake`(記名の自然人の決定)で書く(`kinds/intake.md`)。移行の入力に `templateCommit` を書くと、スクリプトが拒否する。強制層を弱める変更と記録の取り直しを、記名なしで同じ PR に入れられないようにするためである
- 猶予の期間は置かない。この準拠テンプレートが知らない版(既知より大きい `formatVersion`・`schemaVersion`)の構成は、契約検査が失敗にする。読み込みで既定値を補うのは、結果が同じか厳しくなる場合に限る。緩める向きの補いは無い
- D-0 の改訂履歴に行を足さない。版の欄の無いテーラリングの宣言と D-0 を、遡って書き換えない
