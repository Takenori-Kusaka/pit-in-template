# 種別 intake: 準拠テンプレートの更新の取り込み

取り込んだ準拠テンプレートのコミットと、強制層のファイルの要約値を、構成(`process.config.json` の `template`)へ記録し直します(標準 第1章 1.10.3、準拠テンプレートリポジトリの頁「テンプレートの更新の取り込み」)。**要約値を記録し直す経路はこの種別だけです**。変化点に数えません。値を変えません。 <!-- 根拠: IMPL-0323 -->

```json
{ "kind": "intake", "summary": "準拠テンプレートの更新を取り込んだ", "templateCommit": "<取り込んだ準拠テンプレートのコミット。分からなければ書かない>", "decidedBy": "<記名の自然人>", "reason": "<取り込む理由>" }
```

- 決定した者(`decidedBy`)と理由(`reason`)を要する。AI の名義は受け付けない。取り込みは強制層の変更で、AI維持管理者(人)が承認する(`state:needs-platform`)。**AI は記名の欄を埋めない**
- `templateCommit` は、取り込んだ準拠テンプレートのコミットの識別(7〜40 桁の16進)。**推測で書かない**。省くと前の記録を引き継ぎ、記録が無ければ「不明」となる
- 道具が書くもの: `template.commit`・強制層のファイルの要約値(フック・スキル・ワークフロー・ルールセット・ゲートと初期化のスクリプト・アダプタ)・知識ベースの生成元(`kbCommit`)。変化点の記録には、取り直す直前の乖離(変わった・無くなった・増えたパス)と、知識ベースの生成元の前後を書く。第1版の発行の前は、知識ベースの生成元が従う作業中の版を表すため、その切り替えの記録になる
- 形式の版が現行でない構成は、先に種別 `migrate` で移す
- 契約検査は、記録と現在のファイルの不一致を注記に出す(合否に使わない)。PR では基底の記録と比べ、要約値を取り直したパスを注記に列挙する。記録は来歴の主張であって証明ではない
- 要求事項の検査を変える更新は、従う版の切り替え(種別 `edition`)と同時に取り込む(第1章 1.10.3)
- D-0 の改訂履歴に行を足さない
