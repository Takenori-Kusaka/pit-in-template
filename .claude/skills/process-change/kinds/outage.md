# 種別 outage: AI が使えない期間

提供者の障害・利用上限で AI が使えない期間です。**変化点に数えません**。構成は変わりません。期間と、その間の扱い(人へ戻した / 止めた)を記録します。

```json
{ "kind": "outage", "summary": "提供者の障害", "outage": { "from": "2026-10-01", "to": "2026-10-02", "handling": "human" } }
```

| 欄 | 値 |
| --- | --- |
| `from` / `to` | 期間。`to` は継続中なら省略する(「継続中」と記録され、保証の開示にも「継続中」と出る)。終了日を開始日より前にはできない |
| `closes` | 継続中の期間を後から閉じる。開始の記録の `changeLog[]` の添字と、`to`(終了日)を書く。`handling` は、開始の記録と違う場合にだけ書く。**開始の記録は書き換えず、終了日を持つ記録を足す**。例: `{ "kind": "outage", "summary": "提供が戻った", "outage": { "closes": 5, "to": "2026-10-04" } }` |
| `handling` | その間の扱い。`human`(人へ戻した) / `stop`(止めた) |
| `switched` | 別の担い手へ一時的に切り替えた場合は `true`。**切り替えの間は担い手の識別が変わるため、委任を協働へ下げる**。切り替えが終わっても自動では戻らない。戻すときは、種別 `mode` で緩める向きの手続を経る |
| `seats` | 切り替えた席のロール ID の配列。省略すると、委任を宣言している全席を協働へ下げる |

- 席ごとの「AI が使えないときの扱い」(`seats[].fallback`)は、D-0 の担い手の表に事前に決めてある。その扱いと違う対応をした場合も、実際の扱いを記録する
- 期間と扱いは、保証の開示の項目7 と D-0 の改訂履歴に載る
- 障害時の他の記録(当番・復旧・ポストモーテム)は `.claude/skills/artifact/artifacts/incident.md`
