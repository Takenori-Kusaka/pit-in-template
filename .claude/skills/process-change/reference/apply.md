# 適用・残作業・コミット

`/process-change` の手順6・8・9 の詳細です。

## 適用で書き換わるもの

```bash
node scripts/init/generate-profile.mjs --change /tmp/change.json
node scripts/gate/verify-gate-contract.mjs
node scripts/gate/check-d0.mjs
node scripts/gate/check-process-rules.mjs
```

次が書き換わります。**どれも手で編集しないでください**。

| ファイル | 書き換わるもの |
| --- | --- |
| `process.config.json` | 構成と、`changeLog[]` への追記(要約値つき) |
| `PROCESS-PROFILE.md` | 全体 |
| `CLAUDE.md` | 生成区間(`<!-- generated:process-rules -->`) |
| `docs/D-0-governance.md` | 生成区間(節1・節12・節13)、節3 の2行の決定者、frontmatter の `version` |

D-0 の検査は、生成区間が構成と一致することを確かめます。D-0 だけを手で改訂した状態も、構成だけを変えた状態も、ここで検出されます。

構成を変えずに、生成物だけを作り直す場合は次を実行します。構成が変わる再生成(引数で値を変える、回答を変える)は拒否されます。

```bash
node scripts/init/generate-profile.mjs --answers process.config.json
```

## 残作業を利用者へ渡す

手順4 の「残作業」を、**実行せずに**提示します。ブランチ保護の適用コマンド(ルールセットの付け替えを含む)、発行・失効させる認証情報、適合性確認、即時通知です。

- **委任の形は2つある**。開発者の席の規則にだけ該当する変更は、変更ごとの検証を担い手が行い、独立レビュアが人として事前に承認する(現在のブランチ保護のままマージできる)。独立レビュアの席の規則にも該当する変更(G-6 の判定の時点を事後へ移す委任)は、マージの実行が既定で無効であり、組織が有効化するまで協働として扱う。該当はワークフローが判定する(行為する AI 自身には判定させない)。トレーラ `Delegated: <規則ID>` は、どちらの形でも書く
- 委任の規則を登録したのに、確約範囲とコア指定のパス(`delegation.protectedPaths`)が未宣言の場合、残作業に「登録する(無ければ、空の一覧を明示する)」が出る。未宣言のあいだ、どの変更も委任に該当しない
- 委任の規則を追加・拡大したときは、規則の変更を AI維持管理者へ引き渡す(`state:needs-platform`)。`[承認待ち]` のあいだ、その規則では委任は働かない。**差分が変更の主張と一致するかの確認までに留め、許容してよいかを判断しない**
- 安全重要度が上がり委任を適用できなくなったときは、**抜き取り待ちの委任の変更を、協働の手続で全件確認し直す**
- 責任者が未記入の席が、適用するゲートの判定者である場合、そのゲートは止まる。後任を置く、外部の確認者を置く、残った人が兼ねる、のいずれかを利用者に決めてもらう

## コミットする

トレーラは、メッセージの末尾の段落に書きます。`/process-change` が強制層(`.claude/guard.json`・`.claude/settings.json`)を書き換えた場合、コミットは記録だけのコミットに当たらないため、PR を経ずにコミットするなら `Risk` と `Verification` が要ります。`Verification` には、上の3つの検査の結果を書きます。構成の閾値(`ci`・`task`・`guard`)を変えた変化点は、製品のコードと別の PR にします(G-5 の `pr-rules`)。

**独立レビュー(G-6)を適用する体制では、記録だけのコミットに当たらない変化点を PR で入れます**。PR を経ないコミットは、G-6 の判定記録か例外承認の記録が対応づかない限り、出荷判定の証跡で欠落になります(`Risk` と `Verification` を書いても解消しません)。構成・`CLAUDE.md` の生成区間・D-0 体制図・構成書だけを変えたコミット(変化点の記録が追記され、生成区間の外が変わっていないもの)は、記録だけのコミットとして対象外です。

```
chore: 体制の変化点を反映する(<種別>)

- <summary>
- 向き: <緩める / 任免の決定 / 厳しくする / 未達・逸脱の発生 / なし>。決定: <decidedBy>

Risk: R2
Verification: verify-gate-contract・check-d0・check-process-rules が通過
```
