# 差分の出力と、拒否の理由

`/process-change` の手順4 の詳細です。`--dry-run` の出力は、**そのまま利用者へ示します**。要約しません。

## 出力の読み方

| 出力 | 内容 |
| --- | --- |
| 構成の差分 | 回答、ゲートの状態と設定(レビューの方式、出荷判定者の方式)、必須の承認数、ブランチ保護、分離を必須とする組、人の名簿、席(責任者・運用形態・担い手)、委任の規則・変更種別・確約範囲、個別の値 |
| 失効するもの | 3名未満の例外(3名以上になった時)、適合性確認(担い手の識別が変わった時、承認者が離脱した時) |
| 未達の発生・逸脱の発生 / 解消する未達 | 変更後の構成で導出したもの。**人が減った結果として生じたもの、選択の余地がないものに限る** |
| 緩める向き | 向きの判定と、決定できる者。緩める向きを含む変化点は、緩める向きとして扱う |
| 厳しくする向き | 即時に適用する変更。委任の範囲を狭める変更を含む |
| 上限を超えるため引き下げた運用形態 | 席の上限、委任を適用できない案件、適合性確認・記名・規則の不足による引き下げ |
| 無効になった確認の候補 | 責任者または運用形態が変わった席の、仕掛かり中の判定 |
| 兼務禁止と独立性の再判定 | 席の責任者を兼務禁止表へ当てた結果 |
| 残作業 | ブランチ保護、認証情報、適合性確認、即時通知、委任の変更のマージの経路、抜き取り待ちの変更の確認し直し、D-0 の版、人へ戻る判定件数の見込み(直近30日の判定記録) |

## 拒否の理由

**拒否されたら入力を書き換えて回避しないでください**。理由を利用者へ伝えます。

| 拒否の理由 | 意味 |
| --- | --- |
| 変化点の記録と、現在の構成が一致しない | 構成が手で書き換えられている。編集を戻す |
| 入力の値が不正 | 知識ベースに無い回答値、運用形態の値、日付の形式、期間の前後、書けない欄 |
| 席を委任にできない | 出荷判定者・事業決裁者・AI維持管理者・AI運用担当者の席である。CL1 以上・規制業の案件である。責任者・担い手の識別・適合性確認・委任の規則・AI が使えないときの扱いのいずれかを欠く。**拒否の文に、その席で宣言できる上限が出る** |
| 記名を受け付けられない | 名簿に無い名義、担い手の識別と同じ文字列、AI を示す語を含む名義 |
| 決定できる者ではない | 緩める向きの決定者が、対象の席の責任者でも、D-0 表1「体制と運用形態」の決定者でもない。規則の承認者が AI維持管理者の席の責任者でない |
| 名簿の行の差し替え | 既存の行(`id`)の氏名とアカウントを両方とも変えている(足したときの値と比べて両方が異なることになる場合も)。別の人は新しい `id` で足す |
| 名簿の識別が別の人と重なる | 氏名・アカウント・`id` が別の人のものと重なる。氏名どうしが空白・括弧書き・敬称を落として重なる |
| 名簿の表記の変更に記名がない・決定できる者ではない | 氏名だけ・アカウントだけの変更に、決定者の記名と理由が無い。決定者本人の行を本人の記名で変えている |
| 任免の記名がない・決定できる者ではない | 任命・交代・後任の配置に、変更前の決定者(体制から外れていれば組織上の任命権者)の記名と理由が無い。**離脱と後任の任命を同じ入力で出すと、後任の任命の記名を求められる**。離脱だけを先に反映し、後任は別の変化点で出す |
| 回答と名簿が矛盾する | 回答は「確認者なし」(`reviewer-no`)なのに、独立レビュアの席へ開発者と別の人を記入している |
| D-0 体制図が無い・版を下げる・版の形式が不正 | 種別 1〜5 は D-0 が無い状態では適用しない。版の形式は `N.N`(`1.0.0`・`v1.1` は拒否) |
| 日付が不正 | 暦に無い日付、未来の発効日、最後の記録より前の発効日、発効日より後の確認日、変化点より前・未来の通知日 |
| 登録の根拠がない | 変更種別に `basis` の3点が無い。様式の文言(`<…>`)、「—」「未定」「なし」などは記入として扱わない |
| 適合性確認の記録を受け付けられない | 実施者が AI維持管理者の席の責任者でない。承認者が当該の席の責任者でない |
| 委任の規則が登録の要件を満たさない | 全域の指定、変更種別の欠落、標準変更カタログに登録していない変更種別、決定した者の名義 |
| 兼務禁止に抵触する | **3名以上の体制で、同じ人が、兼ねてはならない2つの席の責任者になっている**(開発者 × 独立レビュア、開発者 × 出荷判定者、出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者。10名以上では価値責任者 × 技術判断者)。記名があっても通らない。1〜2名では未達または逸脱として記録する。**拒否の文は、今の名簿の人で解ける割り当て(組の一方の席を誰へ移せばよいか)を出す。利用者へはその候補をそのまま示し、人を増やす案を既定の解き方として示さない**。どれを選ぶかは決定者が決める |
| 名簿の人数と回答が合わない | 名簿の体制内の人数が、チーム規模の回答の範囲を外れている。境界の通過は変化点として回答を改める |
| 納期だけの変更で構成が変わる | 統制を外す要求である。緩める向きの変更として扱う |
| SG の判定記録が実在しない | `sgRecord` が `docs/gates/` 配下の実在する判定記録を指していない |
| 不変条件に反する | AI を利用しない構成で CL2 以上、など。**1〜2名で CL1 以上・規制業になる変化点は拒否されない**(下記) |

## 出荷できない状態

安全重要度 CL1 以上、または規制業の案件で、体制が3名を割った場合、スクリプトは**拒否せずに反映し**、構成へ `shipBlocked: { reason, since }` を立てます。旧い構成のまま止めると、実態と構成が食い違うためです。出力に `[出荷不可]` が出ます。

- 契約検査・D-0 の検査・構成書・`CLAUDE.md` の生成区間に表示され、**出荷判定(G-7)の証跡の集約は失敗する**
- 体制を3名以上へ戻す変化点で解除される。選択肢は、体制を確保する、危害の帰結を設計で下げて区分を下げる(記録を要する)、当該の機能を実施しない、の3つ。**どれを選ぶかをエージェントが決めない**
- 初期化(`/process-init`)で最初から 1〜2名 × CL1 以上を宣言する場合は、拒否される
