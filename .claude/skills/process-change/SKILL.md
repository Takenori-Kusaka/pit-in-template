# 体制の変化点を反映する

人の増減・交代、AI の担い手や運用形態の変更のあと、**最初のゲート判定より前に**、D-0 体制図と構成を改めます(標準 第3章 3.13)。このスキルは変化点の種別を入力に取り、差分を出します(`/process-init` の再実行では、何が失効し何が生じたかを特定できない)。

**`process.config.json` を手で編集しないでください**。書き換える経路はこのスキルだけです(仕組みと限界: `reference/integrity.md`)。

## このスキルが決めないこと

- **統制を緩める向きの変更を、エージェントが決めない**(人の確認を減らす、委任の範囲を広げる、ゲートを省略へ変える)。決定した者の記名と理由を要する。名前と理由を推測で埋めない
- 決定できるのは、対象の席の責任者か、D-0 表1「体制と運用形態」の決定者。任免は向きにかかわらず決定である
- **責任者・決定した者・適合性確認の実施者と承認者・通知先の欄へ、AI の名義を書かない**。人の名簿へ、利用者から受け取っていない名前を足さない
- 無効になった確認のやり直しの要否(文脈オーナーが決める)。ブランチ保護の適用、認証情報の発行と失効、通知(人が行う)

## 種別と補助ファイル

**種別を決めたら、その補助ファイルを1枚だけ読みます**(所在はこのスキルのディレクトリからの相対)。

| `kind` | 変化点 | 補助ファイル |
| --- | --- | --- |
| `accountable` | 責任者の増減・交代・長期の不在、兼務、名簿(初回の記入を含む) | `kinds/accountable.md` |
| `headcount` | 人数の境界の通過(3名未満と3名以上、10名) | `kinds/headcount.md` |
| `mode` | 担い手の運用形態の変更、委任の範囲の変更 | `kinds/mode.md` |
| `performer` | AI の担い手の識別(モデル・指示資産・権限・実行基盤)の変更 | `kinds/performer.md` |
| `axis` | 軸B〜E の入力(ステージ・規制・委託・安全重要度)の変化 | `kinds/axis.md` |
| `settings` | 個別の値(アダプタ・CI の下限・変更規模の上限など)。変化点に数えない | `kinds/settings.md` |
| `outage` | 提供者の障害・利用上限で AI が使えない期間。変化点に数えない | `kinds/outage.md` |
| `notice` | 即時通知の後からの記録、承認権限の一時制限の発動。変化点に数えない | `kinds/notice.md` |
| `schedule-only` | 納期・目的・範囲・予算だけの変更。変化点に数えない | `kinds/schedule-only.md` |

短い不在・セッションの再起動・個々の変更のリスク区分の判定は、変化点に数えません。

**D-0 節3「決定の権限」の手で書く行**(例外承認・要件・受入基準の確定・出荷の可否など)を書く種別はありません。構成から書き込むのは「体制と運用形態」「標準変更カタログへの登録」の2行だけです(`governance`。`kinds/accountable.md`)。ほかの行は人が D-0 を手で書き、PR で入れます。**版(`version`)は上げません**。手で版を上げると、構成の `d0Version` と食い違い `check-d0` が失敗します(`.claude/skills/artifact/artifacts/00-d0-governance.md` の「手で書く節と版」)。

## 手順

1. **現在の構成を読む**(コマンドは `reference/input.md`)。未設定なら先に `/process-init`
2. **変化点を聞く**。種別・対象・変更後の値・発効日を利用者へ確認する。**推測で埋めない**。名簿・責任者・担い手の識別・適合性確認の記録は利用者から受け取る
3. **入力をファイルへ書く**(`/tmp/change.json`)。例は種別の補助ファイル、キーは `reference/input.md`
4. **適用せずに差分を出し、そのまま利用者へ示す**(要約しない)。出力の読み方と拒否の理由: `reference/dry-run.md`。**拒否されたら入力を書き換えて回避しない**

```bash
node scripts/init/generate-profile.mjs --change /tmp/change.json --dry-run
```

5. **向きに応じて進める**。緩める向き・任免は、記名と理由を受け取るまで適用しない。未達・逸脱の発生は記名を待たず即時に適用する。見分け方: `reference/direction.md`
6. **適用し、検査する**。書き換わるファイルと、構成を変えない再生成: `reference/apply.md`

```bash
node scripts/init/generate-profile.mjs --change /tmp/change.json
node scripts/gate/verify-gate-contract.mjs
node scripts/gate/check-d0.mjs
node scripts/gate/check-process-rules.mjs
```

7. **即時通知を記録する**。出力に `[即時通知]` が出たら、通知先と通知日を利用者から受け取る(`kinds/notice.md`)。**エージェントが通知を済ませたことにしない**
8. **残作業を、実行せずに利用者へ渡す**(`reference/apply.md`)
9. **コミットする**(`reference/apply.md`)
10. **次の一手を示す**

```bash
node scripts/gate/next.mjs
```

「人の判断待ち」が出たら、コマンドを実行せず、待つ席へ受信箱のラベルで渡します。

## やってはならないこと

- 構成・D-0 の生成区間・`changeLog[]`・要約値を手で書き換えること。成立済みの判定記録を書き換えること。最初のゲート判定より後へ反映を先送りすること
- 決定した者・通知先・通知日を推測で書くこと。**自分(AI)の名義を書くこと**。離脱していない人を名簿から外して「発生」に見せること
- 委任の規則に当たるかを自分で判定すること。拒否を回避するために種別や回答を書き換えること
