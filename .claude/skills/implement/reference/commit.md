# ブランチとコミット

`CLAUDE.md`「ブランチとコミット」の詳細です。

- トランクベース。`main` は常にリリース可能な状態を保つ
- ブランチ名: `feature/<機能ID>-task-<N>` / `fix/<Issue番号>-<内容>` / `docs/<内容>` / `chore/<内容>`
- コミット種別: `feat` `fix` `docs` `test` `refactor` `chore` `ci`
- コミットトレーラ: `Spec: F-012 / Task-3`(必須。設定・ツール・雛形のファイルだけの PR は `Spec: setup`。製品のコードを含めば通らない)、`ADR: ADR-021`(該当時)、`Co-Authored-By:`(AI が関与した場合は必須。モデルの名称と版を書く)、`Delegated: <規則ID>`(委任の範囲の変更では必須。変更ごとの検証を担い手へ委ねた変更として識別する。R3 の変更に限る。独立した人の事前の承認が無い委任の変更は、G-6 の判定を事後へ移した変更(人の事前確認を経ていない変更)と、それ以外(独立した人の確認を経ていない変更)に分けて数えられる)、`Risk: R1 / R2 / R3 のいずれか`(PR を経ずにコミットする場合は必須。リスク区分は変更ごとに確定する記録であり、PR を経ないコミットは PR 本文の欄を持たない。記録だけのコミットには要らない)、`Verification: <実行した検証と結果の要点、または証跡の所在>`(PR を経ずにコミットする場合は必須。PR 本文の「検証方法と結果」に当たる。1行で書く。記録だけのコミットには要らない)。トレーラはメッセージの末尾の段落に書く(途中の段落のトレーラは読まれない)。PR の変更として数えるのは、PR のマージコミットと一致するコミットだけである。件名に `(#N)` を書いても、main へ直接入れたコミットは PR を経ていないコミットとして扱われる。独立レビュー(G-6)を適用する体制では、PR を経ていないコミットは、G-6 の判定記録か例外承認の記録が対応づかない限り、出荷判定の証跡で欠落になる
- コミットの Author は指示した人間。マージは squash
