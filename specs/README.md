# 機能仕様

`F-NNN/` の下に置きます。

```
specs/
├── F-001/
│   ├── spec.md    受入基準(テンプレ1)。G-2 / G-4 の判定対象
│   └── plan.md    実装計画(テンプレ7)。G-4 の判定対象
└── F-002/
```

`/spec-write` で作ります。

## この2つが揃うまで実装しない

完了の条件を曖昧さなく書けない機能は、書けるところまで分解してから実装へ渡します。エージェントが停滞する原因の多くは能力の不足ではなく、**完了条件の不在**です。

## 曖昧語は CI が止める

受入基準に、合否を一意に判定できない表現は使えない(標準 第4章 G-2 基準2)。類は3つある。逃げ道になる句、程度を定めない副詞・形容詞、末尾を開いた列挙である。

`spec-lint` は、標準 第4章 G-2 の検出語を、機能仕様の受入基準の節から検出し、G-5 を失敗させる。検出語の正本は標準の表である。一覧は次のコマンドで出す。

```bash
node scripts/gate/spec-lint.mjs --terms
```

検出語は、機械が落とす最低限の語である。検出語に無い語でも、類に当たる表現は G-2 で差し戻される。

検出語が、合否を一意に判定できる文の一部として現れる行は、行末に `<!-- spec-lint-ok: 理由 -->` を書いて検出から外せる。理由の無い印は無効である。`spec-lint` は、除外した行の件数と所在を結果に出す。
