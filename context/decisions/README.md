# 判断記録(ADR)

設計上の選択と、採らなかった案を記録します。範囲は標準 第2章 2.6「判断記録の範囲」によります(依存の追加・変更、外部インタフェース、データ形式、構成単位の境界、非機能への影響など。網羅ではありません)。プロセスの構造の変更、安全重要度の引き下げ、記録済みの実装スタックの変更も対象です。

**原則と規約は、ここへ書きません**。恒久層へ置きます(プロダクトの原則は `../standards/principles.md`、様式は `templates/12-product-principles.md`)。選択が可逆であることを理由に、判断記録を省きません。

判断記録は独立の文書です。実装計画・機能仕様・ゲート判定記録・PR の本文へ統合しません。技術設計判断(G-3)の判定の対象は技術上の選択で、判断記録は判定の材料です。判定の証跡はゲート判定記録で、判断記録の番号と版を引きます。

標準は、判断記録の索引(一覧・目次)を求めません(標準 第6章 テンプレ2「判断記録の索引」)。このディレクトリに残る判断記録が、現に効いている判断記録の集合です。

## 命名

`NNNN-<英語のケバブケース>.md`。4桁のゼロ埋め連番。番号は再利用しません。

```
0001-use-postgres.md
0002-session-in-cookie.md
```

## 書き方

`/adr-write` を使うか、`templates/02-adr.md` を写します。

## 採用済みの ADR を書き換えない

採用後に書き換えてよいのは、**状態の行だけ**です。状態の行は本文に含めません。決定を変えるときは**新しい ADR で置き換えます**。

| 状態 | 置き場 | 置き換える側に書くこと(「置き換える決定」の欄) |
| --- | --- | --- |
| 採用 | このディレクトリ | — |
| 一部置き換え(→ ADR-MMM の決定 n) | このディレクトリに残す | `ADR-NNNN の決定 k` |
| 置き換え(→ ADR-MMM) | 同じ変更で `../_archive/decisions/` へ移す | `ADR-NNNN(全部)` |
| 廃止 | 同じ変更で `../_archive/decisions/` へ移す | — |

置き換えられた側の状態の行と、置き換える側の「置き換える決定」の欄が互いを指していることを、`node scripts/gate/check-decisions.mjs` が検査します(CI の contract ジョブ)。移した判断記録は削除しません。

**既存の判断記録の移行**: このテンプレートの更新より前の様式の判断記録は、「置き換える決定」の欄を持ちません。検査はこれを不一致として出します。更新の際に、各判断記録の冒頭へ `- 置き換える決定: なし`(置き換えたものは `ADR-NNNN の決定 k` など)を足し、置き換えられた側の状態の行を4つの語彙へ改めます。状態の行と欄の追加は、採用後に書き換えてよい範囲(状態の行)と、本文を変えない欄の追加に限ります。

期限つきの実験として導入した判断記録は、期限の後に結果を状態の行へ反映します。期限を過ぎて反映されていないものは `node scripts/gate/check-decisions.mjs --overdue` が一覧に出します(四半期の振り返りの入力。扱いは技術判断者が決めます)。

書き換えると、当時なぜそう決めたのかが失われます。**採らなかった選択肢を書き残すことは、後任者が同じ検討を繰り返さないための唯一の手段です**。

## コア機能では添付が必須

コア機能の変更では、独立レビュー(G-6)で該当の ADR を添付します。
